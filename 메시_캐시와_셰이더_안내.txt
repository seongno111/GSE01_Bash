메시 캐시와 셰이더 구조 안내
개정: 2026-09-22

Renderer 배치 사용
  Begin(background)
  월드 Actor들의 DrawCachedMesh / Triangle / Rect / Line / Ellipse / Glow / Text 호출
  BeginUI()                 // 월드 배치 제출 -> 후처리 -> UI 상태 전환
  UI 그리기 호출
  Flush()                   // UI 배치 제출

  도형 호출은 즉시 glDraw를 실행하지 않고 인스턴스 데이터를 누적한다.
  용량 한도나 GPU atlas 재배치가 필요하면 자동으로 중간 제출한다.
  제출 순서와 반투명 합성 순서를 유지하면서 다른 형상/글리프도 한 배치에 포함한다.
  Renderer 외부에서 셰이더/타깃/블렌딩 상태를 직접 변경할 때는 먼저 Flush해야 한다.

메시 수명
  DrawCachedMesh(key, position, scale, builder, tint)를 호출한다.
  같은 키의 메모리 메시가 있으면 재사용한다.
  메모리에 없으면 실행 파일 옆 MeshCache/v1/<키 해시>.mesh에서 읽는다.
  파일도 없거나 유효하지 않으면 builder를 실행하고 로컬 정점을 저장한다.
  파일에서 읽었을 때에는 builder를 실행하지 않는다.
  GPU 컨텍스트가 새로 만들어진 실행에서는 파일 로드 후 최초 GPU 업로드가 필요하다.

  builder는 기존 도형 API로 position/scale이 적용된 좌표를 제출한다.
  그 결과를 position/scale에 대해 정규화하여 로컬 좌표로 저장한다.
  중첩 builder의 정점/tint는 부모 메시에 포함된다.
  키에는 고정 형상, 구워진 색상, 포즈/상태 변형을 빠짐없이 반영한다.
  카메라/월드 위치, 줌, 인스턴스 tint는 키에 넣지 않는다.
  builder 안에서 게임 상태를 변경하거나 매 프레임 필요한 작업을 하지 않는다.
  primitive/ 접두사는 Renderer 기본 도형용으로 예약되어 있다.

적용 대상
  지형 타일, 블록, 나무, 성당, 캐릭터, 적, 한글을 포함한 UI 글리프.
  삼각형/사각형/선/타원/안개는 기본 메시를 공유하여 크기와 색상을 인스턴스로 전달한다.
  타원의 분할 수는 캐시 키에 포함된다. 일반 Quad는 공유 삼각형 두 개로 제출한다.
  불꽃, 체력 바, 그림자, 발사체 등은 정점을 매 프레임 생성하지 않고 기본 도형을 사용한다.
  움직임/크기/색상과 삼각형 참조 목록은 매 프레임 갱신한다.
  카메라 이동과 줌 변경만으로 동일 메시 정점을 다시 만들지 않는다.
  한글 GDI 폰트 지표/래스터 조회는 실행별 별도 메모리 캐시다.

GPU 배치
  정점은 공통 RGBA32F geometry atlas에 저장한다. 메시별 VAO/VBO를 만들지 않는다.
  인스턴스 변환/색상은 texture buffer로, 삼각형 참조는 instanced vertex attribute로 전송한다.
  glDrawArraysInstanced(GL_TRIANGLES, 0, 3, triangleCount)로 원래 순서대로 제출한다.
  GL 인스턴스는 삼각형 단위이고 논리적인 메시 인스턴스는 별도 변환 레코드를 공유한다.
  자세한 선택 이유/한계/예상 드로우콜은 렌더링_성능개선_리포트.txt에 정리했다.

캐시 관리
  최대 atlas 64 MiB, CPU 정점 사본도 보관한다. 인스턴스/폰트 저장소는 별도다.
  메모리 캐시가 프레임 경계에서 4,096개를 넘거나 atlas 공간이 부족하면 오래된 항목을 퇴출한다.
  atlas를 재배치할 때는 누적 배치를 먼저 제출하고 살아 있는 정점만 재업로드한다.
  퇴출된 메시의 파일은 유지되므로 다시 요청하면 파일에서 읽을 수 있다.
  디스크 예산은 버전 폴더별 256 MiB. 초과 시 추가 파일 저장만 생략한다.
  읽기/저장이 불가능해도 메모리 캐시로 그리기를 계속한다.
  GPU atlas 자체를 할당하지 못하면 초기화 오류를 출력한다.

  파일은 버전, 전체 키, 정점 개수, 체크섬과 데이터 범위를 확인한다.
  파일 헤더 24바이트 뒤에 키 원문과 정점 레코드(각 32바이트)가 이어진다.
  Windows little-endian float/정수 형식의 런타임 캐시이며 배포용 범용 모델 형식이 아니다.
  모델링 도구의 mesh를 가져오는 import 파이프라인은 이번 구현에 포함되지 않는다.

  형상/폰트/직렬화 규칙을 변경할 때 RendererMeshCache.cpp의 CacheVersion을 올린다.
  특정 메시만 바꾸려면 InvalidateMesh(key)로 메모리와 파일 캐시를 무효화한다.
  부모에 구워진 중첩 메시 변경은 부모 키도 무효화해야 한다.
  안전하게 게임을 종료한 상태에서 해당 MeshCache 버전 폴더를 지워 전체를 다시 만들 수도 있다.

셰이더
  SimpleGame/Shaders/*.vs, *.fs 파일을 ShaderProgram.cpp가 읽는다.
  SolidRect.vs / .fs: 공통 atlas/인스턴스 배치와 HDR/선형 색상 처리.
  Fullscreen.vs: 후처리 전체 화면 삼각형.
  BloomExtract.fs: 밝은 영역 추출/축소.
  GaussianBlur.fs: 가로/세로 블러.
  PostComposite.fs: 블룸, 가장자리 블러, 비네트, 노출/톤 매핑.
  빌드 후 실행 파일 옆 Shaders 폴더로 복사하는 기존 규칙을 사용한다.
  실행 파일 옆 복사본을 먼저 읽으므로 새 실행 파일과 새 셰이더를 함께 사용해야 한다.

계측
  CachedMeshCount/Bytes: 현재 메모리 캐시의 메시 수/정점 바이트.
  MeshCacheHits/Misses: 프레임 내 메모리 캐시 조회 결과.
  Renderer::Stats(): 생성/파일 로드/업로드/배치/CPU 시간 등.
  세션별 콘솔/CSV 설명은 성능_로그_안내.txt를 참고한다.
  빌드·실행·성능 측정은 사용자 요청에 따라 수행하지 않았다.
