메시 캐시와 셰이더 구조 안내
작성일: 2026-09-14

메시 재사용
  Renderer::DrawCachedMesh에 같은 키를 전달하면 이미 생성한 메시를 재사용한다.
  처음 요청할 때만 생성 콜백을 호출하여 정점을 만들고, 로컬 좌표로 변환한 뒤
  VAO/VBO에 GL_STATIC_DRAW로 업로드한다. 캐시가 유지되는 동안 같은 메시의
  정점 생성과 GPU 업로드를 반복하지 않는다.
  위치, 확대·축소, 색상 배율과 발광 배율은 그리기 시 셰이더에 전달한다.
  카메라 이동이나 창 리사이즈를 이유로 정적 메시를 다시 생성하지 않는다.

적용 대상
  - 블록: 크기와 정점 색상별 공유
  - 나무: 높이를 결정하는 40가지 변형별 공유
  - 성당: 내부 블록과 등불·창문을 포함한 하나의 복합 메시
  - 플레이어·죽음의 잔재: 인간/괴물, 적대 여부, 발사 효과 상태별 본체
  - 레벨 1 일반 적·보스: 등급별 본체
  - 한글을 포함한 UI 글리프: 글자와 픽셀 크기별 공유, 색상·투명도는 매번 전달
  원·타원의 단위 원 좌표도 분할 수별로 보관하여 삼각함수 계산을 재사용한다.

  지형 타일, 불꽃의 변형, 안개, 발사체, 체력 바 등 개별 도형 호출은
  기존 동적 정점 배치를 사용한다. 기존 Triangle/Quad/Line API를 모두
  개별 GPU 메시로 바꾸는 구조는 아니다.
  정적 메시와 동적 배치는 제출 순서대로 그려 반투명 합성 순서를 유지한다.
  HDR 발광 강도는 메시 정점에 보관하며 UI는 후처리 완료 후에 그린다.

추가 오브젝트 구현 규칙
  DrawCachedMesh(key, position, scale, builder, tint)를 사용한다.
  builder는 기존 Renderer 도형 API로 position/scale을 적용한 좌표를 제출한다.
  tint는 생략할 수 있으며 기본값은 흰색, 불투명, 발광 배율 1이다.
  키에는 형상·정점 색·고정 포즈를 결정하는 값을 포함한다.
  월드 좌표, 카메라 위치, 확대 비율, 인스턴스 tint는 키에 넣지 않는다.
  생성 콜백 안에서 게임 상태를 변경하거나 매 프레임 필요한 처리를 하지 않는다.
  서로 다른 모습이 같은 키를 사용하면 최초 생성된 모습이 재사용되므로,
  형상을 바꿀 때에는 키를 변경하거나 InvalidateMesh(key)를 호출한다.
  중첩 호출의 자식 형상과 tint는 부모 메시에 포함되므로 부모 키에도 반영한다.

수명과 메모리
  캐시는 Renderer가 소유하며 종료 시 GPU 자원을 해제한다.
  다음 프레임 시작 시 4,096개 / 정점 버퍼 64 MiB 기준을 넘으면
  가장 오래 사용하지 않은 항목부터 제거한다. 현재 프레임 중에는 일시적으로
  기준을 초과할 수 있으며, 제거된 항목은 다음 요청 시 다시 생성한다.
  이미 제출한 그리기 명령은 메시 소유권을 유지하여 무효화 후에도 안전하게 그린다.
  이 기준은 GPU 메시 캐시에 적용되며 GDI 글리프 정보와 동적 배치는 별개다.
  CachedMeshCount()는 현재 보관 수, MeshCacheHits()/MeshCacheMisses()는
  해당 프레임의 최상위 캐시 재사용/생성 요청 수를 반환한다.

독립 셰이더 파일
  모든 GLSL 소스는 SimpleGame/Shaders 아래의 .vs / .fs 파일에서 읽는다.
  C++ 파일에는 GLSL 소스 문자열을 넣지 않는다.

  SolidRect.vs / SolidRect.fs
    장면과 UI의 공용 정점·색상 렌더링, 메시 위치/크기/색상/발광 배율 적용.
  Fullscreen.vs
    후처리 공용 전체 화면 삼각형.
  BloomExtract.fs
    밝은 영역 추출 및 축소.
  GaussianBlur.fs
    가로·세로 가우시안 블러.
  PostComposite.fs
    블룸, 가장자리 블러, 비네트, 노출과 톤 매핑 합성.

  파일 탐색과 컴파일·링크 처리는 ShaderProgram.cpp로 분리했다.
  Renderer와 PostProcessing은 ShaderProgram.h의 LoadShaderProgram을 사용한다.
  UTF-8 BOM이 붙은 셰이더 파일도 읽을 수 있고 오류 로그에 파일명을 출력한다.
  Visual Studio 프로젝트에 로더를 등록했으며, 빌드 후 .vs/.fs 파일을
  실행 파일 옆 Shaders 폴더에 복사하는 기존 규칙을 사용한다.
  실행 파일 옆 Shaders 폴더를 먼저 검색하고 프로젝트 경로를 대체 경로로 쓴다.
  셰이더는 초기화 시 로드한다. 수정 후 실행 중 자동으로 다시 읽지는 않는다.

사용자 요청에 따라 빌드·실행·렌더링 결과 확인과 성능 측정은 수행하지 않았다.
