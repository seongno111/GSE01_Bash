# 마을 밖 청크 지형 모델 적용

2026-11-02. `Modeling/WorldChunks_v1/README.md`, `chunk_catalog.json`, `validation.json`을 기준으로 청크 지형을 게임에 연결했다. 제작 원본·GLB·제작 카탈로그는 수정하지 않았다. 기존 설정 문서와 `world_biomes.design.json`은 제작 당시의 설계 스냅샷이며, 이 보고서가 현재 코드 적용 범위를 설명한다.

## 적용된 자원

| 구분 | 내용 |
|---|---|
| 기본 지형 | 재바람 초지·검은 수관림·종울음 늪지·유리재 사막·왕도 구릉·화덕 황무지 |
| 기본 지면 | 6종 × 4변형 = 24개 |
| 장소 지면 | 폐촌·수도원·전장·납골 채석장, 각 3변형 × 4청크 = 48개 |
| 지형 전이 | 8개 이웃 조합 × 2청크 = 16개 |
| 전체 지면 | 88개, 각각 OPAQUE 재질·primitive 1개 |
| 공유 소품 | 나무 줄기·분리 수관·쓰러진 과수·늪의 종·수로 아치·망루·화덕·폐우물·회랑·봉인판·깃발 11개 |

`world_chunk_library.glb`와 `chunk_shared_props.glb` 두 파일을 초기화 시 읽는다. 88개 메시를 원점에 모두 그리지 않고 현재 청크에 필요한 노드 하나를 선택한다. 개별 `CHUNK_*.glb`는 제작·검토용이며 런타임에서 중복 로드하지 않는다.

## 생성과 장소 조립

`Terrain::Sampler`는 64월드 단위, 8×8청크를 기준으로 권역을 선택한다. 시드와 권역 좌표에서 계산한 연속적인 생태 단계가 초지→늪→숲→구릉→화덕 황무지→사막으로 이어진다. 인접 권역의 단계 차이를 1 이하로 제한하는 함수이므로 사막과 늪이 바로 붙지 않으며, 각 연결에 제작된 전이 조합이 있다. 같은 지형의 권역이 이어지면 더 큰 지역으로 읽힌다.

현재는 이 연결을 우선한 초기 생성 규칙이다. 기획의 정확한 면적 가중치나 불규칙한 48~96칸 권역 경계까지 구현한 것은 아니다. 8쌍의 전이 자원을 등록하고 현재 생태 단계에 필요한 5쌍을 양방향·가로/세로로 선택한다. 전이 구간은 경계 양쪽 청크를 합한 16칸이다. 교차점에서는 X방향 전이를 우선한다. 제작물에 별도의 2차원 모서리 전이가 없어 일부 교차점의 색 경계는 후속 개선 대상이다.

폐촌 등은 16×16의 **2×2청크 장소**로 생성한다. 시드·위치·장소 종류·변형이 들어간 동일 ID를 4개 부분이 공유하며, 카탈로그의 owner_chunk가 지정한 소품은 해당 부분에서 한 번만 배치한다. 이미 구워진 바닥의 기본 지형 예시와 현재 권역이 맞는 레시피만 선택한다. 다른 기후로 강제 색변환하지 않는다.

장소 배치 요청 확률은 권역당 32%이며 마을·거점·주도로·튜토리얼과 겹치는 후보는 생략한다. 가까운 요청끼리는 위치 기반 우선순위로 정리해 중심 간 64칸 이상을 확보한다. 장소 ID는 재생성 시 같지만, 새 상자·NPC·퀘스트·보스·저장 시스템을 추가한 작업은 아니다. 기존 몬스터·NPC·마을 인구와 웨이브 편성은 유지한다.

## 좌표와 보호 마스크

모델 원점은 기존 청크의 타일 (0,0) 중심이다. `(8*chunkX, 8*chunkY)`에 스케일 1로 배치하고, 로컬 X/Z 범위 -0.5~7.5를 유지한다. 세로·역방향 전이는 (3.5,3.5)를 중심으로 90도 또는 180도 회전해 같은 범위에 맞춘다. 카탈로그의 UV 좌표는 -0.5 원점과 recipe_world_offset을 반영해 실제 소품 위치로 바꾼다. 늪의 종처럼 음수 높이로 배치한 소품도 화면 높이에 반영한다.

보호할 지형은 다음과 같다.

- 마을 반폭 18 + 외관 완충 8칸.
- 적 거점 반폭 12 + 완충 4칸.
- 기존 성소·예배당·부활 주변과 폭 3칸의 주도로.
- 튜토리얼 경작지와 2칸의 외곽 여유.

각 청크는 64개 타일의 보호 여부를 64비트 마스크로 저장한다. 셰이더에서 보호 영역에 걸친 지형 조각을 버리고 그곳에만 기존 타일 바닥을 그린다. 그 결과 제작된 사구·뿌리·돌의 통로가 기존 주도로와 일치하지 않아도 길 위를 덮지 않는다. 청크가 전부 보호 영역이면 새 지면 Actor를 만들지 않는다. 새 지형 영역에서는 기존 타일 바닥·기존 무작위 고사목 배치를 함께 생성하지 않는다.

`ActorLayer::Terrain`을 기존 Ground보다 먼저 그려 보호 영역의 타일, 건물, 유닛의 표시 순서를 유지한다. 지면은 1개 모델 드로우이며 타일별 지면 Actor 64개를 만들지 않는다. GPU 모델 경로가 실패하면 해당 청크의 비보호 영역만 기존 타일 표현으로 대체한다.

## 소품과 통행

큰 소품은 청크의 자식 `TerrainPropActor`로 배치한다. 보호 경로는 소품의 기준점뿐 아니라 전체 지면 범위를 확인해 겹치지 않게 한다. 줄기·화덕 등 카탈로그의 blocking_candidate는 최대 반경 0.65의 간단한 원형 충돌을 사용하며 청크당 충돌 소품을 하나 이하로 제한한다. 아치·회랑·수관 등은 장식으로 사용한다. 이는 정밀 메시 충돌이나 완전한 건물 외벽 충돌을 뜻하지 않는다.

로드된 구역은 SceneGraph의 소품 Actor 충돌, 원거리 구역은 **같은 ChunkPlan의 소품 좌표와 반경**을 사용하도록 연결했다. 조회를 위해 GLB나 메시를 새로 만들지 않는다. 실제 플레이에서의 경로·전투·재방문 검증은 수행하지 않았다.

수관은 별도 메시로 그리며 플레이어의 화면 위치를 덮는 범위에서는 수관만 숨겨 시야를 확보한다. 줄기와 충돌은 유지한다. 실제 지면 높이 추적·수영·감속·익사·지형 피해·플레이어 오염 누적은 추가하지 않았다. 기존 죽음·정화·잔재 규칙을 사용한다.

## 캐시와 분석 로그

CPU 지형 계획은 LRU 캐시 1024개로 제한한다. 방문·로딩 순서와 무관하게 시드·좌표로 다시 만들 수 있고, 캐시에서 내보냈다고 적이나 보상을 새로 생성하지 않는다. GPU 정점 버퍼·정적 포즈·노드별 인덱스 버퍼는 기존 모델 캐시를 공유한다. 보호 마스크는 uniform 값이므로 청크 좌표마다 별도 GPU 메시를 생성하지 않는다.

지면 라이브러리는 실제 정점 500,211개이므로 첫 GPU 업로드 비용과 메모리는 기존 프로파일 로그의 model_uploads·geometry_upload_bytes 등으로 확인해야 한다. 이후 프레임마다 재업로드하는 구조는 아니다. 지면 본체 드로우는 비보호/부분 보호 청크당 1회이고 공유 소품·기존 보호 타일·후처리 드로우는 별도다. 실측 FPS나 성능 개선 배율은 주장하지 않는다.

```text
[WorldChunks] ready grounds=88 baseVariants=24 placeVariants=12 transitionPairs=8 sharedProps=11 sourceFiles=2
[WorldChunks] generator=1 seed=... regionSide=64 chunkSide=8 planCacheLimit=1024 collision=shared-plan
[WorldChunks] place=... chunk=... model=...
[WorldChunks] streamCreatedGrounds=... keptTileCells=... sharedPropInstances=... transitions=... placeParts=... loadedChunks=... planCache=.../1024 hits=... misses=...
```

streamCreatedGrounds 등은 **이번 스트리밍에서 새로 만든 수**다. 프레임당 드로우 수는 기존 `[Profile]`과 CSV를 사용한다. 로딩 검사가 실패하면 `[WorldChunks] unavailable: ...`와 원인을 기록하고 기존 지형을 사용한다.

## 정적 검토와 실행 확인 범위

`doc/tools/inspect_world_chunks.py`로 실제 공용 GLB와 제작 카탈로그를 읽어 검사했다.

- 배포 파일 132개의 바이트 크기·SHA-256과 기준 문서 스냅샷.
- 기본 24·장소 48·전이 16 메시의 참조가 겹치거나 누락되지 않음.
- 실제 8×8 외곽 범위, 경계 윗면 높이 0, 중심 기준 90도 회전 후 범위.
- 단일 primitive, OPAQUE, COLOR_0, 정적 노드의 단위 변환과 외부 텍스처 미사용.
- 2×2 장소의 4개 부분·소품 소유 청크·UV/높이 메타데이터.
- 프로젝트 등록과 C++/GLSL uniform·varying 이름 대응.

결과는 `지형_청크_모델_정적검토_2026-11-02.json`, 복사 기록은 `지형_청크_모델_배포_2026-11-02.json`이다. **C++/GLSL 빌드·게임 실행·실제 화면·통행·FPS 검증은 수행하지 않았다.**

사용자가 다음 빌드 후 마을 밖으로 이동해 지형 변화와 도로 보호를 확인할 수 있다. 동일 비교가 필요하면 EMBER_WORLD_SEED를 같은 값으로 사용한다. 시작 마을과 완충대는 기존 지면을 유지하므로 그 바깥에서 확인한다. CPU/GPU 캐시의 이전 자원은 게임 재시작으로 갱신한다.
