# 공통 이동 애니메이션과 모델 회전 적용

2026-10-29. 현재 제작 규격인 `Modeling/LocomotionShared_20261029/README.md`와 `locomotion_catalog.json`을 기준으로 적용했다. `DirectionalMotion_20261029`의 README도 확인했으며, 해당 폴더는 폐기한 제작 이력으로 취급한다. 제작 원본·GLB·카탈로그는 수정하지 않았다.

## 이동과 방향

각 리그의 기본 이동은 **Walk 하나, Run 하나**다. 정지 시 같은 Idle을 사용하고, 이동 방향에 따라 다른 클립을 선택하지 않는다. 플레이어·일반 NPC·변이 캐릭터/NPC·기존 몬스터·신규 몬스터·죽음의 잔재에 공통 모델 회전을 적용했다.

`Prototype::MoveActor`가 충돌 처리 후 알려주는 실제 이동량을 프레임 단위로 합산한다. 입력 방향이나 길 찾기의 다음 목적지를 그대로 사용하지 않으므로 벽을 타고 이동할 때도 실제 진행 방향을 향한다. GLB의 정면은 +Z이므로, 월드 이동량 `(dx, dy)`의 목표 yaw는 `atan2(dx, dy)`다. 렌더러에서 모델 정면은 월드 평면의 `(sin(yaw), cos(yaw))`가 된다.

| 화면 이동 | 월드 이동 방향 | 목표 yaw |
|---|---|---:|
| 위 / W | (-1, -1) | -135° |
| 오른쪽 / D | (+1, -1) | +135° |
| 아래 / S | (+1, +1) | +45° |
| 왼쪽 / A | (-1, +1) | -45° |
| 오른쪽 아래 | (+1, 0) | +90° |
| 왼쪽 아래 | (0, +1) | 0° |
| 오른쪽 위 | (0, -1) | ±180° |
| 왼쪽 위 | (-1, 0) | -90° |

이 표는 현재 고정 등각 투영을 기준으로 한 대응이며, 실제 모델 회전은 8방향에 제한되지 않는다. yaw 차이를 ±π 범위의 최단 각도로 구하고 프레임 시간에 따른 지수 보간을 한다. 평면 yaw만 회전하므로 지면 회전의 최단 경로 쿼터니언 보간과 같은 회전 경로다. 정지 후에는 마지막 목표 방향을 유지하며, AI 경로 갱신 사이에도 회전은 매 화면 프레임 진행된다.

이동 중에는 이동 방향을 우선하고, 정지 중 공격할 때는 공격 시작 시의 표적 방향을 향한다. NPC와 기존 몬스터의 공격 시작에도 방향을 기록했다. 실제 피해·발사·회복·공격 타이머는 기존 로직을 따른다. 모델의 root yaw를 더하거나 음수 스케일로 뒤집지 않아 왼손 램프·오른손 검의 배치와 삼각형 방향을 보존한다.

## 클립 선택과 위상

- 주인공: HERO_Walk / HERO_Run. 변이 시 MON_03_Walk / MON_03_Run.
- NPC: NPC_Walk, 도주 시 NPC_Run. 변이 NPC도 같은 기준으로 MON_03 클립을 사용한다.
- 기존 몬스터·잔재: 각 MON_00~04의 공통 이동 클립을 사용한다.
- 신규 몬스터: 종별 Walk를 기본으로 하고 추격·협공·도주 시 Run을 사용한다. 정상 이동에서 FlankL/R, Flee, Backstep으로 방향을 표현하던 선택은 제거했다.
- 공격·시전·도약·돌진 Travel·방벽 등 개별 행동은 전용 클립을 유지한다. 이때도 모델 전체 방향은 같은 yaw 경로로 전달한다.

이동량을 부드럽게 추정한 기존 보행 위상을 Walk/Run이 공유한다. 한 주기는 두 발의 교차를 포함하며 기존 3.6 월드 단위/주기 기준과 최대 1.8주기/초 제한을 유지했다. 방향이 바뀌거나 Walk↔Run이 바뀌어도 발 위상을 다시 시작하지 않는다. 포즈 전환은 기존 0.12초 혼합을 사용한다. 리그별 정밀한 발 미끄러짐 보정은 실제 실행 화면에서 추가 조정할 수 있다.

## 변경 위치

- `GameActors.h`, `WorldActors.cpp`: 실제 이동 방향 누적, 목표 yaw, 최단 각도 보간, 정지 방향 유지, 공통 이동 클립 선택.
- `Renderer.h`, `RendererModels.cpp`: `DrawModel`에 yaw를 직접 전달한다. 좌우 두 개의 고정 각도 분기를 제거했다. 건물·성문의 기존 yaw 호출도 새 인수 순서로 맞췄다.
- `ModelActorVisuals.cpp`, `PlayerActor.cpp`, `EchoActor.cpp`, `EnemyActor.cpp`: 캐릭터별 공통 클립과 Actor yaw 연결.
- `ModelMonsterSpecies.cpp`, `ModelLibrary.h`, `MonsterModelVisuals.cpp`: 신규 몬스터의 Walk/Run 등록·중립 root yaw 검사, 기본 이동 선택 통일.
- `NpcActions.cpp`, `NpcOutposts.cpp`: 정지 공격의 표적 방향 기록.
- `SimpleGame.vcxproj`: `locomotion_catalog.json`을 기존 런타임 모델 복사 대상에 포함.

회전은 GPU uniform 값으로 전달한다. 방향마다 메시를 생성하거나 파일을 다시 읽지 않으며 기존 CPU/GPU 자원 캐시를 사용한다. 모델 드로우 수와 건물 회전 방식도 유지한다. 3D를 사용할 수 없을 때의 기존 2D 스프라이트는 좌우 표시를 그대로 사용한다.

## 검토와 배포

`doc/tools/inspect_shared_locomotion.py`로 현재 전달본 37개 파일의 SHA-256·크기를 확인했다. 13개 리그와 18개 GLB에 해당 Walk/Run이 각 하나씩 있고, 중립 root 회전·제자리 이동·루프·골격·웨이트·클립 메타데이터가 일치하는지 검사했다. 방향별 Screen/Turn 클립이 현재 GLB에 없고, 보존된 고유 클립 합계가 186개인 것도 확인했다. 신규 몬스터는 정리 후 87개이며 이전 123개 검사 상수를 실제 제작 카탈로그 기준으로 갱신했다.

검토 보고서:

- `공통_이동_회전_에셋검토_2026-10-29.json`
- `공통_이동_기본팩검토_2026-10-29.json`
- `공통_이동_몬스터검토_2026-10-29.json`

현재 GLB 18개와 관련 런타임 카탈로그·검수·이동 규약 JSON을 합해 29개 파일을 기존 `x64/Debug/Modeling`, `x64/Release/Modeling`에 복사하고 원본과 SHA-256을 비교했다. 복사 결과는 `공통_이동_에셋배포_2026-10-29.json`에 기록했다. 이전 방향별 백업을 현재 실행 에셋으로 복사하지 않았다.

**빌드·게임 실행·렌더링 확인은 수행하지 않았다.** 사용자가 다음 빌드 후 실행하면 새 회전 코드와 최신 모델을 함께 확인할 수 있다. 실행 중 로드된 CPU/GPU 모델은 캐시되므로 게임을 재시작해야 한다.
