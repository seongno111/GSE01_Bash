# 주인공 무기별 애니메이션 적용

2026-11-05

## 적용 자료

Modeling/HeroWeaponAnimations_v1/README.md와 animation_catalog.json을 기준으로 무기별 GLB 7개를 적용했다. 제작 원본과 전달 파일은 수정하지 않았다. 새 30개 클립을 로딩하며, 기존 Hero_v1의 공통 11개 동작은 본 이름으로 대응해 가져온다. 서로 다른 GLB의 노드 인덱스가 같다고 가정하지 않는다.

| 무기 | 대기 자세 | 기본 공격에서 번갈아 재생하는 동작 |
| --- | --- | --- |
| 지팡이 | HERO_Staff_Ready | CastBolt / CastSweep |
| 철퇴 | HERO_Mace_Ready | Strike / Sweep |
| 도끼 | HERO_Axe_Ready | Chop / Cleave |
| 망치 | HERO_Hammer_Ready | Smash / Uppercut |
| 창 | HERO_Spear_Ready | Thrust / Sweep |
| 단검 | HERO_Dagger_Ready | Stab / Slash |
| 활 | HERO_Bow_Ready | Nock → Draw → Aim → Release |

근접 공격은 기존의 단일 대상 판정을 유지한다. Sweep/Cleave라는 동작 이름만으로 광역 피해를 추가하지 않는다. Guard 5개와 Staff Channel은 로딩해 두었으며, 현재 없는 방어·집중 스킬 입력과 효과를 임의로 추가하지 않았다.

## 이동과 장착

카탈로그 upper_body_mask에 속하는 본의 Ready 동작을 공통 HERO_Walk/HERO_Run 하체와 로딩 시 조합한다. 양손 무기의 파지를 유지하며 방향은 기존 Actor 회전으로 처리한다. 공격 중에는 잠근 대상을 향해 회전하고 이동 입력도 유지한다. 방향별 스프라이트는 사용하지 않는다.

전용 GLB에는 무기가 이미 스킨으로 장착되어 있다. 정적 무기를 다시 부착하지 않는다. 카탈로그 hide_original_meshes와 hide_lamp_light를 적용해 활·망치·창의 등불을 숨긴다. 대장간의 모델 미리보기는 기존 개별 무기 GLB를 유지한다. 전용 에셋 로딩 실패 시 오류를 로그에 남기고 기존 정적 장착으로 대체한다.

## 판정과 시간

공격 시작 시 대상 ID와 피해량을 저장한다. 카탈로그 melee_contact/cast_release/projectile_release 시점에 시뮬레이션 업데이트가 한 번만 피해 또는 탄체를 발생시킨다. 화면 밖이나 낮은 렌더링 빈도에서도 렌더러가 공격 판정을 실행하지 않는다. 타격 순간 대상의 생존·PK 가능 여부·사거리·장애물을 재검사하며, 새 대상으로 피해를 옮기지 않는다.

공격 간격 전체에 준비·타격·회수 동작을 배분한다. 최대 3배속을 적용해 높은 레벨에서도 전체 동작이 지나치게 압축되지 않도록 했다. 실제 간격은 기존 레벨별 간격과 해당 무기의 가장 긴 공격 길이 / 3 중 큰 값이다. 대장간 카드도 같은 WeaponCooldown 함수를 사용한다. 기본 활 간격은 이전 수치 0.65초에서 실제 0.74초가 되며, 다른 무기의 1레벨 기본 간격은 유지된다. 고레벨에서는 애니메이션 길이 하한이 먼저 적용될 수 있다.

활의 원본 시간은 Nock 0.75 + Draw 0.80 + Aim 유지 0.12 + Release 0.55 = 2.22초다. 조준은 2초 루프의 앞부분을 짧게 사용한다. 발사는 Release 시작 후 원본 0.10초에 맞춘다. 1레벨 실제 발사는 전체 공격 시작 약 0.59초 뒤다. 조준 구간에서 잠근 대상을 잃거나 사거리·장애물 조건을 만족하지 못하면 Lower로 회수하고 탄체를 만들지 않는다.

사망·무기 교체·대장간 열기·변이 상태 변경 시 예약된 공격을 취소한다. 기존 쿨타임은 교체나 UI 열기로 초기화하지 않는다. 변이 상태에서는 기존 몬스터 동작을 사용한다.

## 활의 변형과 성능

GLB POSITION/NORMAL morph target과 weights 채널을 추가로 읽는다. 최대 4개 타깃을 지원하며 지원 범위를 벗어난 데이터는 명시적으로 거부한다. STEP, LINEAR, CUBICSPLINE 보간 경로에 weights를 연결하고 기본값과 자세 전환 블렌딩에도 반영한다.

활대와 시위의 Draw, 화살의 Hide를 원본 데이터 그대로 사용한다. Release의 화살 Hide는 STEP으로 0에서 1로 바뀐다. 변형을 GPU에서 스키닝 전에 적용한다.

정점·인덱스·변형량은 에셋별 GPU 버퍼에 한 번 올린다. 매 프레임 메시 생성이나 정점 버퍼 재업로드 없이 기존 본 행렬 버퍼에 작은 변형 가중치만 추가한다. 현재 활의 변형 노드 3개는 프레임당 192바이트의 추가 자세 데이터를 사용한다. 무기별 모델도 기존과 같이 한 번의 모델 드로우로 그린다. 공통 셰이더의 정점당 변형 참조 필드가 12바이트 추가되므로 실제 GPU 시간은 실행 프로파일로 확인해야 한다.

로그:

- [HeroAnimation]: 무기 키, 전용 클립 수, 공격 변형 수, 이동 조합 수.
- [ModelAssets]: GLB별 로딩 시간, 메시·정점·삼각형·스킨·클립 수.
- [ModelGPU]: 최초 업로드 정보. 자세 전송량은 기존 modelPoseBytes/instanceBytes 통계에 포함된다.

## 정적 확인과 사용자 실행 확인

7개 GLB의 기존 본 이름 대응과 upper_body_mask 대응을 확인했다. 새 30개 클립의 2,988개 채널에 대해 키 시간의 증가, 값의 유한성, 카탈로그 길이, 이벤트의 클립 내부 위치를 확인했다. 활 전용 파일에 화살·활대·시위의 morph 타깃이 각각 하나씩 있으며, Release 화살 Hide가 이벤트 시점에 STEP으로 0→1이 되는 것을 확인했다. 30/60/120Hz의 시간 경계 계산에서 발사 임계값이 한 번만 처리되는 것도 별도로 확인했다. 이는 소스와 데이터의 정적 확인이며 게임 동작 테스트 결과는 아니다.

사용자의 기존 지시에 따라 빌드와 게임 실행은 수행하지 않았다. 빌드 시 기존 CopyPrototypeAssets 항목이 새 GLB와 animation_catalog.json을 실행 폴더에 복사한다.

사용자 확인 항목:

1. 대장간에서 7종 교체, 대기 자세와 두 공격 변형, 등불 표시 확인.
2. 활·망치·창의 이동 시 양손 파지와 공격 중 대상 방향 확인.
3. 활 장전·시위 당김·발사 시 화살 숨김·대상 소실 시 회수 확인.
4. 타격/시전 순간 피해와 탄체 발생, 사거리 이탈·사망·교체·UI 열기 시 잔여 판정 취소 확인.
5. 높은 레벨에서 공격 간격과 UI 수치 일치, 첫 표시 이후 modelUploads가 계속 늘지 않는지 확인.
6. 같은 장소에서 변경 전후 FPS, modelDraws, modelPoseBytes와 GPU 시간을 비교.
