# 유닛 보행·좌우 방향·플레이어 공격 애니메이션

작성일: 2026-10-19

이 문서는 최초 6프레임 구현 기록이다. 이후 12프레임 확장과 atlas 배치 변경은 [애니메이션 12프레임 확장](애니메이션_12프레임_확장_2026-10-19.md)을 참고한다.

## 적용 범위

- 플레이어, NPC 5직군, 일반 몬스터 2종, 보스, 변이 캐릭터에 각각 6프레임 보행을 적용한다.
- 사망 후 남는 변이 잔영(Echo)과 적 거점에서 생성되는 몬스터에도 같은 보행 경로를 사용한다.
- 플레이어의 인간/변이 상태에 각각 6프레임 공격을 적용한다. NPC·몬스터의 공격 모션은 이번 범위에 포함하지 않는다.
- 화면 좌우 방향은 스프라이트의 가로축을 반전한다. 위아래 이동은 기존 좌우 방향을 유지한다. 정면/후면 전용 리소스는 추후 확장 대상이다.
- 기존 플레이어/NPC의 사인파에 의한 몸 전체 상하 이동을 제거한다. 발을 기준으로 실제 보행 자세를 교체한다.

## 상태와 게임 로직 연결

`UnitAnimation.h`의 `UnitSpritePose`는 이동 여부, 좌우 방향, 보행 주기, 공격 진행률을 렌더러에 전달한다.

`Prototype::MoveActor`에서 충돌 처리가 끝난 실제 이동량을 `GameActor::RecordMovement`에 전달한다. 입력 키만 눌렀거나 벽에 막혀 위치가 바뀌지 않으면 보행 주기도 진행하지 않는다. 보행 한 주기는 월드 거리 2.2이며, Shift 달리기 때는 실제 속도에 비례해 프레임 전환도 빨라진다.

NPC와 거점 몬스터의 20Hz 갱신 및 경로 노드를 넘기는 동안에는 마지막 이동 상태를 최대 120ms 유지한다. 보행 주기는 정지나 경로 노드 변경으로 초기화하지 않아 느린 NPC도 양발 전체 주기를 완료한다. 상태와 주기는 게임 시간/이동량으로 계산하므로 화면에 보이는지와 관계없이 갱신되며, Draw에서 타이머를 증가시키지 않는다.

좌우 판단은 등각 투영의 화면 가로 이동인 `dx - dy`를 사용한다. 아주 작은 가로 성분은 무시한다. 공격 시에는 목표를 향한 방향을 잠시 고정하고, 공격 중 실제 이동 방향은 다음 보행 방향으로 저장한다.

`FireProjectile`이 실제로 발사체를 생성한 경우에만 공격 클립을 시작한다. 공격 모션은 발사/뻗기 → 후속 동작 → 반동 → 복귀 순서이며, 기존 투사체 발사 타이밍이나 피해 계산을 지연하지 않는다. 길이는 발사 쿨타임에 따라 0.22~0.32초이다. 자동 공격과 스페이스 공격 모두 같은 경로를 사용한다.

플레이어 사망 후 이동, 일반 적 재생성, 거점 적 재생성 시 애니메이션 상태를 초기화한다. 순간 이동 거리는 보행 거리로 누적하지 않는다.

## 리소스

| 파일 | 배열 | 용도 |
| --- | --- | --- |
| `SimpleGame/Assets/unit-walk-humans-v1.png` | 6열 × 6행 | 플레이어, 성직자, 기사, 모험가, 약탈자, 상인 |
| `SimpleGame/Assets/unit-walk-monsters-v1.png` | 6열 × 4행 | 언데드, 오염 전사, 보스, 변이 캐릭터 |
| `SimpleGame/Assets/player-attack-v1.png` | 6열 × 2행 | 인간 플레이어, 변이 플레이어의 공격 |

총 보행 60프레임, 공격 12프레임이다. 정지 시에는 해당 보행 클립의 첫 포즈를 사용해 정적 이미지와 스타일이 바뀌는 현상을 피한다.

기존 `realistic-atlas-v1.png`를 외형 참조로 내장 `image_gen` 도구를 사용했다. 생성과 여백 보정 프롬프트는 각 PNG와 같은 이름의 `.prompts.json`에 저장했다. 원본 정적 atlas는 건물·환경과 누락 리소스의 대체 표시를 위해 유지한다.

생성 이미지의 실제 투명 여백을 읽어 프레임 경계를 찾는다. 명목상 격자 좌표만 사용하면 무기나 망토가 잘릴 수 있으므로 가까운 안전한 alpha 구분선을 사용한다. 같은 클립에서는 공통 크기 기준을 쓰고 발을 고정해, 프레임별 외곽 크기가 달라져도 몸통이 확대·축소되지 않게 한다.

## 렌더링 비용과 로그

- PNG 디코딩과 GPU 텍스처 업로드는 초기화 시에만 수행한다.
- 정적 atlas와 3개 애니메이션 시트를 시작 시 하나의 GPU 텍스처로 묶는다. 프레임별로 텍스처를 교체하거나 flush하지 않는다.
- 기존 `sprite/unit-quad-v1` 공유 메시와 순서 보존 인스턴싱을 사용한다. 유닛 한 개의 본체는 여전히 사각형 1개/삼각형 2개이다.
- 매 프레임 바뀌는 값은 UV, 좌우 변환, 색상 및 발광 영역 등 인스턴스 데이터이다. 애니메이션용 메시를 매번 만들거나 디스크에서 읽지 않는다.
- 인스턴스에 프레임별 발광 영역을 추가해 5개의 RGBA32F texel, 80바이트를 사용한다. 직전 정적 스프라이트 구현의 64바이트보다 인스턴스당 16바이트 증가한다. 정적 메시 캐시 파일 형식은 바꾸지 않는다.
- 플레이어의 등불 밝은 영역은 프레임마다 초기화 시 찾는다. 피부·갑옷·가죽 전체가 발광하지 않도록 제한하며, 좌우 반전에도 같은 발광 영역이 따라간다.
- `[Assets] Packed sprite atlas` 로그에 크기, 정적 셀 수, 보행/공격 클립 수, 전체 프레임 수, 등불 영역 수, GPU 상주 바이트를 출력한다. 정상 리소스에서는 `staticCells=16`, `walkClips=10`, `attackClips=2`, `animationFrames=72`가 기대값이다.
- 리소스 누락·잘못된 격자·GPU 크기 제한 시 이유를 로그로 남기고 사용 가능한 정적 스프라이트로 대체한다.

기존 프로파일의 DrawCalls, meshBuilds, diskLoads, geometryBytes, instanceBytes, GPU 단계 시간을 함께 비교하면 애니메이션의 추가 비용을 구분할 수 있다. 실행 성능 수치는 이번 작업에서 측정하지 않았다.

## 확인 범위와 실행 확인 항목

사용자 요청에 따라 게임 빌드와 실행 결과 확인은 수행하지 않았다. 소스 연결, 프로젝트 리소스 등록, 셰이더/인스턴스 레이아웃, 이미지 alpha 경계와 프레임 수를 정적으로 확인했다. 아래 항목은 사용자가 빌드 후 확인할 항목이다.

에셋 분석 결과는 `유닛_애니메이션_에셋검토_2026-10-19.json`에 파일 해시, 이미지 크기, alpha 구분선, 각 프레임의 외곽, 등불 영역과 함께 저장했다. 모든 정적 셀 16개 및 애니메이션 프레임 72개가 유효하며 인간 플레이어의 보행/공격 12프레임 모두 등불 영역이 검출된다. 예상 GPU atlas는 3714×2284, RGBA8 33,931,104바이트(약 32.36MiB)이다. 이는 파일/코드 분석값이며 실제 렌더러 실행 로그를 측정한 값은 아니다.

1. WASD 좌우 이동 시 발이 교대로 움직이며, 방향을 바꾸면 이미지가 가로로 반전되는지 확인한다.
2. 위아래 이동과 정지에서는 마지막 좌우 방향이 유지되고, 벽을 누르고 있어도 보행 주기가 계속 진행하지 않는지 확인한다.
3. Shift 달리기에서 보행 주기가 빨라지는지 확인한다.
4. 자동 공격/스페이스 발사 시 목표 방향으로 공격 포즈가 나오고 복귀하는지 확인한다. 이동 중 발사, 최대 공격 속도도 포함한다.
5. 오염으로 변이한 플레이어와 사망 후 남은 잔영의 보행, 변이 플레이어의 공격을 확인한다.
6. 마을 이동/순찰 중인 NPC, 적 거점 순찰/습격 몬스터, 보스의 보행과 발 위치를 확인한다.
7. 좌우 방향 및 보행/공격 프레임 변화 중 등불 Bloom이 유지되는지 확인한다.
8. 빌드 후 출력 `Assets` 폴더에 새 PNG 3개가 복사되고, 시작 로그에 10개 보행/2개 공격 클립이 표시되는지 확인한다.

## 후속 확장 지점

정면/후면 이미지와 추가 행동 클립은 `UnitSpritePose`의 방향/행동 상태와 렌더러의 클립 선택을 확장하면 된다. NPC·몬스터 공격은 각 전투 시스템의 실제 공격 시점에 연결하되 플레이어와 같은 클립 재생 경로를 사용할 수 있다. 현재 프레임은 프로토타입용 생성 에셋이므로 보폭, 의복 연속성, 손 위치의 미세 조정은 실행 화면 확인 후 보완할 수 있다.
