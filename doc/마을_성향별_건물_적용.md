# 마을 성향별 3D 건물 적용

`Modeling/Villages_v1`의 2026-10-26 전달본을 현재 6개 마을에 연결했다. 모델 원본은 변경하지 않았다. 실행 기준은 `VillageDefinition.id`이며 카탈로그의 표시명이나 배치 전시 좌표로 기존 월드를 덮어쓰지 않는다.

## 마을 대응

| 마을 ID | 게임 마을·문화 | 적용되는 건축 분위기 |
|---|---|---|
| cathedral | 성당 마을 / 자비와 상호부조 | 낮고 넓은 맞배지붕, 목재 보강, 공동체 건축 |
| dawn | 새벽 수도촌 / 신앙과 정화 | 높은 급경사 지붕, 첨두창, 밝게 바랜 석재 |
| iron | 철벽 주둔촌 / 규율과 무력 | 두꺼운 석벽, 평지붕·여장, 병영 형태 |
| market | 황금 장터 / 교역과 부 | 우진각 지붕, 돌출 상층, 차양·간판·황동 |
| seekers | 잿빛 탐구촌 / 탐험과 깨달음 | 팔각 탑, 원추 지붕, 관측 장식·비대칭 부속실 |
| outlaws | 검은 이빨 소굴 / 약탈과 힘 | 비스듬한 외쪽지붕, 철판 보강, 말뚝과 붉은 천 |

각 테마의 HOUSE_A, HOUSE_B, CHAPEL, WORKSHOP, GATE, WALL, 총 36개 모델을 사용한다. 현재 마을의 고유 문화를 기준으로 선택한다. NPC 이사·사망·주민 성향 변화로 society.alignment 수치가 변해도 건물이 매번 다른 테마로 바뀌지는 않는다.

## 중심 건물 개정

2026-10-27의 중심 건물 6종 갱신 내용과 배포·검토 결과는 [마을 중심 랜드마크 적용](마을_중심_랜드마크_적용_2026-10-27.md)에 기록했다. 아래 내용은 기존 테마 건물의 배치·크기·자원 공유 구조다.

## 실제 배치

- 기존 주택 kind 7, 성당 kind 5, 작업장 kind 8, 담장 kind 2는 해당 위치가 속한 마을의 `game_kind_choices`에서 모델을 선택한다.
- 기존 주택 좌표는 유지하고 A/B를 좌표의 블록 번호로 번갈아 배치한다. 마을 전체가 로드되면 기존 주택 36채는 A/B 각 18채다. 카메라 이동·청크 재생성으로 선택이 달라지지 않는다.
- 각 마을 중심에서 동서남북 18단위에 있는 기존 출입로에 성문을 하나씩 추가한다. 6개 마을 합계 최대 24개이며 해당 청크와 함께 로드/해제한다.
- 성문은 `VillageGateActor`라는 별도 Actor다. 기존 프롭 번호를 재사용하지 않으며 새로운 충돌체를 추가하지 않는다. 문짝 개폐나 통행 제한 기능이 없는 장식용 열린 문이다.
- 담장과 성문은 바깥쪽, 주택·작업장·성당의 전면은 마을 중심 쪽을 향하도록 90도 단위로 회전한다. 회전은 GPU의 모델 방향 값으로 처리하므로 방향마다 새 메시를 만들지 않는다.
- 마을 밖 적 거점의 주택·폐벽과 일반 랜드마크는 기존 공통 모델을 사용한다. 마을 성소 화로와 훈련 허수아비도 기존 모델을 유지한다.

## 크기와 이동 공간

건물의 실제 GLB 바인드 좌표를 읽어 지면 X/Z의 최대 절댓값을 구하고, 아래 범위에 맞도록 필요한 경우에만 균일 축소한다. Blender Z-up 기준 카탈로그 치수를 GLB의 Y-up 좌표로 잘못 해석하지 않도록 메시에서 직접 구한다.

| 종류 | 지면 최대 반경 기준 | 목적 |
|---|---:|---|
| 주택·작업장 | X/Z 각 축의 절댓값 최대 1.65 | 4단위 블록 사이에 최소 0.7의 시각적 간격 |
| 성당 | 최대 2.15 | 기존 중심 광장과 접근로 범위에 맞춤 |
| 담장 | 최대 1.2 | 기존 3단위 담장 간격에서 겹침 완화 |
| 성문 | 원래 크기 | 넓게 비워 둔 기존 출입로에 배치 |

기존 `MakeTile`, 마을 중심·크기·도로·NPC 집 위치, `PropActor::ColliderRadius`, 멀리 있는 지형의 충돌 조회는 변경하지 않았다. 시각적인 외관 교체이므로 모델 전체의 정확한 건물 충돌체를 자동 생성하지 않는다. 기존 충돌 영역과 외관이 완전히 일치하지 않는 부분은 후속 충돌체 작업의 대상이다.

6개 성문 모두 실제 삼각형을 읽어 가운데 폭 0.6m, 높이 2m의 통과 구간에 겹치는 삼각형 AABB가 없는지 보수적으로 검사했다. 성문 Actor 자체의 충돌 반경도 기존 Actor 기본값 0이다. 이 검사는 실제 플레이 이동이나 정밀 충돌 검증을 대신하지 않는다.

## 자원·구현

`village_buildings.glb` 공용 라이브러리 하나를 읽고 이름으로 건물을 선택한다. 개별 마을 GLB 6개를 중복 로드하거나 36개 메시를 한 위치에 전부 그리지 않는다. 기존 GPU 정점·정적 변환 버퍼 및 파트 선택 인덱스 캐시를 공유한다. 마을/종류/주택 변형에 대한 선택은 Actor가 처음 그려질 때 캐싱한다.

`village_catalog.json`과 `validation.json`의 스키마·검수·36개 모델 참조·테마 소속·타입을 확인한 뒤 한 번에 등록한다. 팩이 불완전하면 사유를 기록하고 기존 공통 프롭으로 표시한다. 관련 로그는 `[VillageModels] theme=... kind=... model=... scale=...`, 정상 완료는 `[VillageModels] ready themes=6 meshes=36 sharedFiles=1`이다.

| 파일 | 변경 |
|---|---|
| `SimpleGame/ModelVillageBuildings.cpp` | 테마 팩 로드·검증·크기 계산·선택 API |
| `SimpleGame/ModelLibrary.h/.cpp` | 마을 건물 자원과 초기 로딩 연결 |
| `SimpleGame/Villages.h` | 성문 위치와 바깥 방향 계산 |
| `SimpleGame/WorldActors.cpp`, `GameActors.h` | 기존 프롭의 테마 선택과 성문 Actor |
| `SimpleGame/World.cpp` | 청크 생성 시 출입로 성문 배치 |
| `SimpleGame/Renderer.h`, `RendererModels.cpp` | 정적 모델의 회전 값 전달 |
| `SimpleGame.vcxproj` 및 filters | 새 소스와 village_catalog.json 배포 등록 |

## 검토 결과

`doc/tools/inspect_village_buildings.py`로 실제 GLB·카탈로그·게임 마을 ID 대응, 36개 모델의 테마 소속, OPAQUE/비텍스처 재질, 크기 제한, 18/18 주택 변형, 성문 통과 구간과 방향, 프로젝트 등록을 검사했다. 보고서는 `doc/마을_건물_정적검토.json`이다.

추가로 소스 정렬·공백, 기존 지형 생성과 충돌 함수의 유지 여부를 확인한다. 사용자 요청에 따라 **빌드·게임 실행·실제 렌더링 확인은 수행하지 않는다.**
