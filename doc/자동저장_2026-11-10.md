# 게임 진행상황 자동저장

작성일: 2026-11-10

## 동작

게임 실행 중 실제 경과 시간 기준 120초마다 현재 상태의 스냅샷을 저장한다. 게임 창 최소화 중에도 목표 20Hz로 업데이트를 유지하므로 자동저장 일정이 계속 처리된다. 시스템 절전 등으로 게임 업데이트 자체가 중지되는 동안에는 저장하지 않으며, 업데이트가 재개되면 기한을 확인한다. 첫 시작 시 초기 월드를 한 번 저장하고, ESC 또는 창 닫기로 정상 종료할 때도 마지막 상태를 저장한다. 강제 종료나 전원 차단 시에는 마지막으로 완료된 저장 시점부터 이어진다.

재실행하면 저장본을 자동으로 읽는다. 저장된 월드 시드를 지형 생성 전에 적용하므로 같은 월드에서 이어진다. 저장본이 있으면 EMBER_WORLD_SEED 환경 변수보다 저장본의 시드가 우선한다. 종료되어 있던 시간만큼 월드 시뮬레이션을 추가 진행하지 않는다.

리셋, 새 게임, 저장 삭제 버튼이나 단축키는 추가하지 않았다.

## 파일 위치와 복구

- 기본 저장: `%LOCALAPPDATA%\TheLastEmber\Saves\autosave.json`
- 이전 정상 저장: `autosave.json.bak`
- 쓰는 동안의 임시 파일: `autosave.json.tmp`
- 중복 실행의 동시 쓰기를 막는 파일: `autosave.lock`

실행 폴더나 작업 디렉터리와 무관한 사용자별 경로다. Debug/Release에서 같은 진행상황을 사용한다. 파일 형식은 TheLastEmber / 버전 1이며, JSON 본문에 FNV-1a 64비트 검사값을 붙여 손상을 검출한다. 이 검사값은 변조 방지 암호화가 아니다.

임시 파일을 완전히 쓰고 FlushFileBuffers를 수행한 뒤 ReplaceFileW로 기존 저장본을 교체한다. 이전 본문은 백업으로 남긴다. 첫 저장은 MoveFileExW로 설치한다. 잘못 쓰인 임시 파일은 불러오기 대상으로 사용하지 않는다.

기본 저장본의 형식·검사값·필수 필드·주요 범위를 확인하고, 실패하면 백업을 검사한다. 백업으로 복구한 직후에는 손상된 기본 파일을 정상 백업 위에 복사하지 않는다. 두 파일 모두 유효하지 않으면 원본을 보존하고 자동 쓰기를 중지하며, 화면과 콘솔에 알린다. 이 경우 화면에 생성된 임시 월드는 기존 저장본을 덮어쓰지 않는다. 다른 실행 파일이 같은 저장 경로를 사용 중일 때도 두 번째 프로세스의 저장을 중지한다.

불러올 때 Actor ID를 새 SceneGraph의 ID로 재대응한다. NPC Entity의 주민 번호와 몬스터 목록 순서는 유지한다. 마을 이동과 전서구 통신도 복원한 시뮬레이션 시각에서 계속 진행된다.

화면 이펙트, 발사되어 날아가는 탄체, 현재 공격의 준비/타격 동작, NPC의 진행 중인 단일 행동과 자원 예약, 탐색 중인 경로는 세션 상태로 취급한다. 재시작 시 취소하고 AI가 다시 판단한다. 이미 거래·축복·피해로 변경된 재화와 체력은 저장하며, 완료된 효과를 다시 실행하지 않는다. 마을 임무와 이주 목적 자체는 유지한다.

## 구조와 성능 기록

- ProgressSave: 파일 경로, 자동저장 일정, 스냅샷 취득, 파일 쓰기 작업, 불러오기·복구.
- SaveData / SaveTypes: 런타임 포인터가 없는 저장용 값 구조와 JSON 변환, 기본 유효성 검사.
- NpcSave: NPC 월드의 경제·외교·사건·전서구·거점 상태와 ID 재대응.
- LevelOne: 저장된 시드를 먼저 적용한 뒤 월드를 만들고 상태를 복원.

게임 스레드에서는 프레임 종료 시 값만 복사한다. JSON 변환·검사값 계산·파일 쓰기는 std::async 작업 하나에서 처리하며, 작업이 진행 중이면 다음 쓰기를 중첩하지 않는다. 작업자는 SceneGraph, Actor, OpenGL 객체에 접근하지 않는다. 정상 종료 시에는 진행 중인 저장을 기다리고 마지막 스냅샷 저장까지 완료한다.

콘솔 로그:

- `[Save] path=... intervalSeconds=120`
- `[Save] started captureMs=...`: 게임 스레드의 스냅샷 복사 비용.
- `[Save] complete bytes=... writeMs=...`: 직렬화·검증·디스크 쓰기 전체 작업 비용.
- `[Save] rejected=... reason=...`: 불러오기 실패와 백업 시도.
- `[Save] failed/disabled`: 쓰기 실패 또는 원본 보호를 위한 저장 중지.

## 확인 범위

프로젝트 소스 등록, 필터 등록, 초기화·종료 경로, ID 재대응, 저장 실패 시 원본 보존 흐름을 정적으로 점검했다. 사용자의 기존 지시에 따라 빌드와 게임 실행은 하지 않았다. 실제 저장·불러오기와 성능은 실행 확인이 필요하다.

사용자 실행 확인 항목:

1. 첫 실행의 저장 완료 메시지와 위 경로의 JSON 생성 확인.
2. 무기 교체·경험치 획득·오염 증가·이동 후 2분 경과 시 새 저장 완료 로그 확인.
3. 정상 종료 후 재실행하여 위치·장비·재화·오염·보스 진행·변이 잔재 복원 확인.
4. NPC 사망·이주·거점 웨이브·전서구 전달 중 종료 후 복원 확인.
5. 테스트용 사용자 환경에서 기본 저장본 손상 시 백업 복구, 두 저장본 오류 시 덮어쓰기 중지 확인.
6. 자동저장 시 captureMs와 프레임 로그를 비교하고 종료 시 마지막 저장 완료 확인.

저장 파일을 직접 편집하거나 손상 시험을 하기 전에는 별도 복사본을 보관한다. 게임에는 저장 삭제나 리셋 기능을 제공하지 않는다.
