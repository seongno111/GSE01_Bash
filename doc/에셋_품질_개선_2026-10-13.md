# 에셋 품질 개선 기록 — 2026-10-13

## 목표와 적용 범위

단순 도형과 큰 머리 중심의 표현을 줄이고, 기존 2.5D 중세 종말 세계에 맞는 인체 비율과 재질을 추가했다. 천의 주름, 낡은 가죽, 긁힌 철갑, 풍화된 석재, 이끼와 나무껍질을 표현한 투명 스프라이트 16종을 제작하여 실제 Actor 렌더링 경로에 연결했다.

이미지는 3D 렌더링 풍의 2D 에셋이다. 실시간 3D 모델·PBR 조명·방향별 보행 애니메이션을 추가한 것은 아니다. 현재 인물은 한 방향의 이미지와 작은 이동 바운스를 사용한다. 성소, 훈련장 표식, 무덤, 아이템, 불꽃 등 일부 보조 요소는 기존 도형 표현을 유지한다.

건물은 이미지의 가장 앞쪽 바닥 끝과 월드 좌표 중심이 다르므로, 성당 32px·집 22px·장터 16px·벽 12px·바위 7px·나무 17px만큼 이미지 아래쪽 기준점을 보정했다. Actor의 월드 위치, 깊이 정렬 기준, 충돌 반경과 NPC 경로는 유지한다. 건물의 정확한 통행 여유와 접촉 위치는 실제 화면에서 최종 확인이 필요하다.

## 렌더러와 버퍼

- `RendererSprites.cpp`: Windows WIC로 PNG를 시작 시 한 번 디코딩한다. 외부 이미지 라이브러리 설치는 필요하지 않으며 Windows SDK의 WIC/COM을 사용한다.
- PNG의 약 4등분 위치 주변에서 투명한 행·열을 찾는다. 현재 파일의 열 경계는 `[0,313,627,940,1254]`, 행 경계는 `[0,320,627,943,1254]`다. 생성 이미지의 여백이 정확한 격자와 달라도 머리·첨탑·나뭇가지가 잘리지 않게 분리한다.
- 각 셀의 alpha > 8 영역을 시작 시 한 번 조사하여 UV와 종횡비를 저장한다. GPU에는 전체 PNG를 RGBA8 텍스처 한 장으로 업로드한다. 원시 색상 메모리는 6,290,064바이트(약 6MiB)다.
- 모든 에셋은 `sprite/unit-quad-v1`의 동일한 사각형 메시를 재사용한다. 사각형은 시작 시 미리 캐시한다. 에셋별 메시 생성이나 매 프레임 이미지 디코딩·업로드는 하지 않는다.
- 기존 triangle instancing 제출 순서 안에서 도형과 스프라이트를 함께 그린다. 에셋 하나를 그릴 때마다 flush하거나 별도의 draw call을 발행하지 않는다. 실제 draw 수는 배치 용량과 UI/후처리 패스에 따라 달라지므로 프로파일 로그로 확인해야 한다.
- 인스턴스는 변환·배치 정보·색상·UV를 담는 64바이트(4 RGBA32F texel) 구조로 확장했다. 정적 메시의 Vertex 형식과 기존 디스크 캐시 포맷은 변경하지 않았다.
- 기존 버퍼 용량 재사용 및 스트리밍 경로를 유지한다. 후처리가 바인딩을 변경하므로 각 flush에서 에셋 텍스처를 unit 2에 다시 바인딩한다.
- straight alpha 블렌딩과 앞뒤 제출 순서를 유지한다. HDR 장면에서는 텍스처의 sRGB를 선형 공간으로 한 번 변환한다. 밉맵 없이 선형 필터링하며 셀 가장자리 UV는 반 픽셀 안쪽에 둔다.
- `SolidRect.fs`에서 플레이어 등불, 성당과 집의 창문 영역만 골라 밝은 주황색·황색 텍셀에 HDR 강도를 더한다. 기존 Bloom 후처리가 이 빛을 퍼뜨린다. 셀 ID·로컬 UV 영역·색상·밝기를 함께 검사하여 천과 피부, 갑옷 전체가 빛나는 것을 피한다. 이 영역은 현재 아틀라스에 맞춰 작성했으므로 그림을 교체하면 함께 갱신해야 한다.
- 에셋을 찾지 못하거나 디코딩·분할·업로드에 실패하면 콘솔에 `[Assets]` 원인을 기록하고 기존 도형 표현으로 대체한다.

## 지면 표현

초록색 평면 위의 반복 선을 줄이고 저채도 흙·회색 석재 중심으로 조정했다. 길에는 작은 포장석, 일반 지면에는 불규칙한 돌과 미세한 음영을 배치한다.

지면 메시 키는 바탕 1종, `terrain/v3/paving/0..7` 8종, `terrain/v3/detail/0..63` 64종으로 제한했다. 위치·색상·줌은 인스턴스 값이다. 무한 월드의 타일 좌표마다 다른 메시 파일을 만드는 방식은 사용하지 않는다. 새 v3 키가 이전 장식 메시를 잘못 재사용하지 않도록 한다.

## 프로젝트 포함 및 검증

`RendererSprites.cpp`와 PNG를 Visual Studio 프로젝트에 등록했다. 기존 `CopyPrototypeAssets` 빌드 타깃에서 `Assets/*.png`를 실행 파일 옆 `Assets` 폴더에 복사한다. 소스 트리에서 실행할 때 사용할 경로 탐색도 포함한다.

소스·셰이더 인터페이스, 인스턴스 레이아웃, 프로젝트 XML, PNG 알파 분할, 코드 정렬과 diff를 정적으로 확인했다. 16개 셀의 유효 영역과 투명 분리선을 확인했고, 발광 대상으로 선택한 세 에셋 모두 마스크 안에 HDR 강도 1을 넘는 불투명 텍셀이 존재함을 이미지 데이터로 확인했다. 이 검사는 GPU 실행 결과 확인을 대신하지 않는다. 요청에 따라 빌드·게임 실행·FPS 측정은 수행하지 않았다.

사용자 확인 시 시작 로그의 `[Assets] ... cells=16 ... startup upload only`를 확인하면 새 에셋 로딩 여부를 알 수 있다. 성당 앞·집 옆 통행, 이름표 위치, 변이·보스 표시, 창문·등불 Bloom, 확대/축소 시 가장자리, 동일 장소의 프로파일 로그를 확인하면 좋다.

## 제작 기록

도구: 내장 `image_gen.imagegen`. 투명 배경으로 새 아틀라스를 생성한 뒤, 같은 도구의 이미지 편집 모드로 셀 여백을 보정했다. 최종 사용 프롬프트 전문과 실제 크기·셀 순서는 `SimpleGame/Assets/realistic-atlas-v1.prompts.json`에 기록했다. 요청 프롬프트의 예시 해상도와 실제 출력 해상도는 다르므로 코드에서는 실제 PNG 크기를 사용한다.

다음 시각적 확장 시에는 방향별 걷기·공격·사망 프레임, 직군별 외형 변형, 지면 전용 텍스처, 명시적인 발광 마스크를 같은 아틀라스/배치 구조 위에 추가할 수 있다.
