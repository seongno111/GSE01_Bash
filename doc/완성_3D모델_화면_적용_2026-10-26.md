# 완성된 3D 모델의 게임 화면 적용

2026-10-26. `Modeling/LowPolyKit_v3`와 `Modeling/Hero_v1`에 이미 완성된 GLB를 게임 렌더링 경로에 연결했다. 모델 원본이나 신규 모델을 제작하지 않았다. 빌드와 게임 실행은 사용자 지시에 따라 수행하지 않았다.

## 적용 대상

| 게임 대상 | 사용하는 기존 모델 | 연결한 표현 |
|---|---|---|
| 플레이어 | `Hero_v1/hero_rigged.glb` | 후드·견갑·롱소드·왼손 램프, 대기/걷기/달리기/공격 |
| 정상 NPC 5직군 | `LowPolyKit_v3/npc/npc_parts_rigged.glb` | 주민 ID/직군별 21슬롯 조립, 이동·공격·생활 행동 |
| 메마른 망자 | `monsters/WitheredHollow_rigged.glb` | 대기·이동·공격 |
| 오염된 약탈자 | `monsters/TaintedRaider_rigged.glb` | 대기·이동·공격 |
| 경작지 수문장 | `monsters/FieldWarden_rigged.glb` | 대기·이동·공격·광역 공격 준비 |
| 변이한 플레이어/NPC | `monsters/MutatedHuman_rigged.glb` | 변이체 모델·이동·공격 |
| 죽음의 잔재 | `monsters/DeathEcho_rigged.glb` | 추적 이동·대기·쓰러진 상태 |
| 기존 맵의 프롭 kind 1~10 | `props/props_library.glb` | 고사목·폐벽·바위·묘표·성당·화로·주택·작업장·허수아비·거점 봉화 |

프롭 번호는 `asset_catalog.json`의 `game_prop_mapping`을 사용한다. 모델 33개를 전부 월드에 새로 배치하는 변경은 아니다. 게임에 이미 배치되는 10종의 표시를 해당 모델로 교체한다. 지형·안개·투사체·체력바·UI는 기존 경로를 유지한다.

아직 3D 모델이 없는 잿니 늑대, 역병 등곰, 가시관 사슴, 대공 아자르, 타락한 성기사·사제는 이전 단계의 단순 도형을 유지한다. 기존 사람형 메시를 다른 종족의 대체 모델로 재사용하지 않는다. `MonsterKind` 값과 모델 라이브러리의 숫자 인덱스가 충돌하지 않도록 기존 0~2, 변이체 3, 잔재 4를 명시적으로 연결했다.

## 렌더링 구조

`RendererModels.cpp`와 독립 셰이더 `Shaders/Model.vs`, `Model.fs`를 추가했다. GLB의 인덱스 삼각형과 스킨 웨이트를 GPU 정점 버퍼로 올리고, 본의 월드 행렬과 역바인드 행렬을 포즈 텍스처 버퍼로 전달한다. 실제 3D 정점과 법선을 변형해 그리며, 모델을 PNG로 굽거나 매 프레임 CPU에서 새 메시를 만들지 않는다.

공유 모델 파일마다 정점 버퍼 하나를 캐싱한다. NPC의 여러 파트와 재질은 하나의 공용 정점 데이터에 보관하고, 선택한 파트 조합의 인덱스 버퍼를 캐싱해 **인스턴스당 한 번의 glDrawElements**로 그린다. 재질 색·발광·금속도·거칠기·unlit·alpha cutoff는 정점 속성에 담는다. 현재 완성본은 모두 이미지 텍스처가 없는 OPAQUE 재질이므로 이 경로에 맞는다. 이미지 텍스처를 가진 후속 모델에는 별도의 이미지 업로드 경로가 필요하며, 현재는 경고와 기존 화면 표현으로 복귀한다.

정적 프롭은 바인드 변환 버퍼도 공유하며 프레임마다 업로드하지 않는다. 움직이는 캐릭터는 포즈 행렬만 재사용하는 스트리밍 버퍼에 기록한다. NPC 조립은 모델 ID/직군/장비 행동이 바뀔 때 수행한다. 보행 위상과 좌표는 메시 캐시 키에 넣지 않는다. 애니메이션 포즈는 화면에 그려지는 캐릭터에 대해서만 계산한다.

프로토타입은 기존 SceneGraph의 2.5D 그리기 순서를 유지한다. 모델을 그리기 전에 대기 중인 2D 배치를 제출하고, 모델 내부의 앞뒤 표면에는 깊이 검사를 적용한다. HDR 장면 FBO에 깊이 버퍼를 추가했고 PostProcessing을 끈 경우의 기본 화면에도 깊이 버퍼를 요청한다. 각 모델 뒤에는 다시 기존 2D 상태로 돌아간다.

이는 전체 월드를 하나의 깊이 공간에서 그리는 통합 3D 렌더러가 아니다. 서로 다른 큰 오브젝트가 복잡하게 교차하는 경우에는 기존 발 위치 기반 정렬의 한계가 남는다. 또한 서로 다른 액터를 한 번에 그리는 3D 하드웨어 인스턴싱은 아직 적용하지 않았다. 파트마다 드로우콜을 발생시키는 대신 한 액터의 파트를 합쳐 제출한 단계다. 많은 NPC가 한 화면에 보일 때에는 추가된 모델 전용 계측으로 비용을 확인하고 다음 배치 최적화를 결정한다.

## 좌표·크기·방향

GLB의 Y 위, 정면 +Z, 미터 좌표를 그대로 사용한다. 기본적으로 모델 1m를 현재 월드 1단위로 두고 수직 40픽셀, 지면의 기존 `(x-z)*40`, `(x+z)*20` 투영에 연결했다. 기존 카메라·줌·충돌체·이동 속도는 변경하지 않았다. 주인공의 후드 포함 높이는 약 1.96m다.

유닛은 기존 좌우 방향 상태를 실제 Y축 회전으로 표현한다. 음수 스케일로 메시를 뒤집지 않아 검·방패·램프의 좌우 부착 관계와 법선 방향이 유지된다. 위아래 이동의 별도 정면/후면 상태는 기존 범위대로 추가하지 않았다. 환경 모델은 기본 방향을 사용한다.

## 애니메이션 연결

`ModelActorVisuals.cpp`에서 각 액터의 모델 인스턴스와 재생기를 유지한다. 처음 표시할 때 바인드 포즈에서 천천히 변하는 대신 첫 동작을 즉시 샘플링해 A포즈가 보이는 시간을 피했다. 이후 클립 전환은 0.12초 크로스페이드다. 걷기·달리기는 기존에 완화한 보행 위상을 공유해 20Hz NPC 갱신이 모델 프레임 점프로 보이지 않도록 했다.

플레이어의 롱소드 동작은 기존 공격 시각의 정규화된 진행률에 맞춰 재생한다. **기존 자동 조준 발사체 공격과 피해 판정을 검 근접 공격으로 바꾸지 않았다.** NPC 공격은 직군별 준비/회복 시간과 실제 공격 클립을 대응시킨다. 생활 행동은 카탈로그의 perform/recover와 직군 대응을 사용하고, 작업·치료·휴식 등의 손 장비 교체 요청도 적용한다. 훈련에서 재사용하는 공격 클립은 시각적으로 반복한다.

모델 이벤트는 게임플레이 함수를 호출하지 않는다. 원래 시뮬레이션의 피해·발사·회복과 중복으로 처리하지 않도록 시각 재생 중 발생한 이벤트는 소비만 한다. 들어 있는 모든 141개 클립을 모두 새 상태 머신에 연결한 것은 아니다. 방향 전환 클립, 플레이어 램프 살펴보기·피격·사망 전이, 앉기/무릎꿇기의 별도 진입·이탈 전이는 후속 단계다. NPC와 잔재의 기존 사망 상태에는 DeadHold를 사용한다.

## 램프·재질·후처리

Hero GLB가 요구하는 `KHR_lights_punctual`을 읽도록 로더를 확장했다. 현재 완성본에 들어 있는 점광원을 지원하며, 아직 지원하지 않는 스폿/방향 광원은 명시적으로 거부한다. 램프의 본에 연결된 점광원 위치를 포즈에서 구해 주인공 모델 표면에 따뜻한 빛을 더한다. 광원 세기는 현재 장면 노출에 맞춰 보정한다.

램프 불꽃과 프롭의 emissive 및 emissive strength는 선형 HDR 값으로 전달해 기존 Bloom에 포함한다. 주광과 주변광, 법선 기반 음영을 추가하고 기존 비넷·가장자리 흐림·노출 설정을 유지했다. 램프가 주변 모든 지형과 다른 액터를 동적으로 비추거나 그림자를 만드는 기능은 포함하지 않았다. 현재 모델의 첫 점광원은 해당 모델의 표면 조명에 사용하고 발광 메시의 퍼짐은 Bloom이 담당한다.

## 로딩·빌드 파일·진단

완성된 Hero 카탈로그·검증 JSON·GLB를 선택한 LowPolyKit의 형제 `Hero_v1` 폴더에서 읽는다. 성공하면 Player()는 실제 주인공을 반환한다. 실패하면 사유를 `[ModelAssets] hero unavailable`에 남기고 기존 NPC 프리셋을 사용할 수 있다. 기본 모델 패키지가 없거나 셰이더/모델이 준비되지 않으면 이전 2D 표시 경로가 동작한다.

`hero_catalog.json`, Model 셰이더 및 새 C++ 파일을 프로젝트와 빌드 후 자원 복사에 등록했다. `.blend`나 제작 스크립트를 런타임에서 실행하지 않는다. 파일은 게임 시작 시 읽고, 매 프레임 디스크를 조회하지 않는다.

`[ModelGPU] uploaded`에 공유 정점·인덱스·팔레트 수를 남긴다. 기존 glDraw 집계에 모델 호출을 포함하고, 프로파일 CSV 스키마를 4로 올려 다음 열을 덧붙였다.

- `model_draws`: 해당 프레임의 실제 3D 모델 드로우콜
- `model_uploads`: 해당 프레임에서 처음 GPU에 올라간 공유 모델 수
- `model_pose_bytes`: 해당 프레임의 동적 포즈 업로드 바이트. 정적 프롭의 최초 변환 버퍼는 geometry_upload_bytes에 포함된다.

콘솔/세션 요약의 `Models/frame`에서도 확인한다. 성능 향상이나 프레임 방어를 실행 측정한 결과는 아직 없다.

## 정적 검토

기존 `inspect_modeling_assets.py`에 Hero 검사도 추가했다. v1·v2·v3의 실제 GLB 및 336명 외형 참조 검사에 더해 Hero의 25개 파트, 33개 본을 사용하는 스킨, 17개 클립, 점광원, 바인드 행렬과 웨이트를 검사했다. 결과는 `doc/3D모델_적용_에셋검토_2026-10-26.json`에 남겼다.

현재 주요 GLB에 외부 이미지가 없고 OPAQUE 재질임을 확인했다. 프로젝트의 C++/셰이더 등록, 좌우 회전의 행렬식과 화면 방향, 소스 정렬·공백도 검사했다. **C++ 빌드, GLSL의 드라이버 컴파일, 게임 실행과 실제 화면 검증은 하지 않았다.** 빌드 후 `[ModelAssets] ready`, `[ModelGPU] uploaded`와 셰이더 오류 로그를 확인하고 캐릭터 외형·이동·장비·프롭·Bloom을 확인하면 된다.
