# 모니터링 중 게임 비정상 종료 분석

2026-10-20. 기존 실행 파일의 Windows 오류 기록과 크래시 덤프를 읽어 분석했다. 게임을 새로 빌드하거나 실행하지 않았다.

- Windows 오류: `0xc0000005`, 모듈 `SimpleGame.exe`, 상대 주소 `0x108a4`.
- 기존 실행 파일과 함께 생성된 PDB로 주소를 해석한 위치: `Prototype::MoveEnemy`, `Combat.cpp:151`.
- 분석한 덤프: `SimpleGame.exe.17500.dmp`. 유효하지 않은 주소 `0xffffffffffffffff`를 읽다가 종료되었다.
- 남아 있는 모니터 스냅샷은 시뮬레이션 46초, 진단 로그는 40.05초까지 저장되었다. 모니터를 켠 뒤 약 10초라는 체감과 별개로, 주기적 파일 출력 자체가 원인인 크래시는 아니다.

마을 규모 확장에서 튜토리얼 전투 구역을 동쪽으로 24칸 옮겼다. `LevelOneCell`은 새 원점을 반영했으나, 일반 몬스터의 장애물 우회 로직은 목적지 X를 예전 4~22로 제한했다. 변환된 목적지 인덱스가 -1인데도 `m_LevelWalkable[goal]`을 검사했고, `vector<bool>`의 범위 밖 메모리에 접근했다. 몬스터가 우회를 시도하는 순간 발생하므로 종료 시점은 상황에 따라 달라진다.

일반 몬스터도 `FindRoute`의 공용 월드 탐색과 기존 경로 캐시를 사용하도록 수정했다. 전투 구역 전용 인덱스 접근과 옛 원점 가정을 제거했다. 반환된 경로는 크기를 확인한 뒤 참조하며, 실패 시 재탐색 간격을 둔다. 일반 몬스터의 경로 호출·탐색량도 기존 프로파일 집계에 합산한다.

정적 검사로 `MoveEnemy`에서 튜토리얼 배열과 과거 좌표 범위 참조가 제거된 것을 확인했다. 실행 재현 및 수정 후 런타임 검증은 사용자 요청에 따라 수행하지 않았다.
