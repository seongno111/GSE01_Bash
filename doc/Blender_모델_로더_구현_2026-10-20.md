# Blender 모델 로더 구현

2026-10-20. `Modeling/README.md`, v1·v2·v3 README, 실제 GLB 및 JSON 카탈로그를 기준으로 구현했다. Blender 편집 원본과 제작 스크립트는 수정하지 않았다.

## 적용 범위

게임 시작 시 `Prototype::InitializeLevelOne`에서 `ModelLibrary`를 초기화한다. `.blend` 파일을 직접 해석하거나 Blender를 실행하지 않고, 제작 문서에서 지정한 GLB/glTF 2.0 전달 파일을 읽는다. v1·v2 정적 메시와 v3 스켈레탈 메시를 동일한 자원 API로 제공한다.

이번 변경은 **모델 로딩·공유·외형 조립·애니메이션 평가 계층**이다. 기존 게임 화면은 2D 렌더러와 기존 에셋으로 계속 그린다. 3D 정점/인덱스 GPU 업로드, 스키닝 셰이더, 월드 투영·깊이 정렬을 연결하는 렌더러 변경은 포함하지 않는다. 로드 성공을 실제 화면의 모델 교체 완료로 해석하면 안 된다.

## 소스 구성

| 파일 | 역할 |
|---|---|
| `SimpleGame/ModelAsset.h/.cpp` | GLB/glTF 파싱, 정점·인덱스·재질·노드·스킨·클립 소유 |
| `SimpleGame/ModelAnimation.cpp` | TRS 행렬, 계층 평가, 키 보간, 포즈 전환, 스키닝 팔레트, 이벤트 알림 |
| `SimpleGame/ModelLibrary.h/.cpp` | 패키지 탐색·검증·캐시, NPC 조립, 몬스터·프롭·행동 대응 |
| `doc/tools/inspect_modeling_assets.py` | 게임 실행 없이 실제 GLB와 카탈로그를 읽는 정적 검사 도구 |
| `doc/모델링_로더_에셋검토_2026-10-20.json` | 검사 수치와 입력 파일 SHA-256 |

종속 헤더 cgltf v1.15, nlohmann JSON v3.12.0과 MIT 라이선스를 `SimpleGame/Dependencies`에 고정해 포함했다. 런타임 다운로드는 필요 없다.

## 패키지 선택과 추가 에셋

1. 지정한 경로가 있으면 해당 경로만 사용한다. `Initialize(path)`에 Modeling 폴더 또는 개별 패키지 폴더를 전달할 수 있다.
2. 기본 탐색은 `EMBER_MODELING_ROOT`, 실행 파일 위치와 상위 폴더들의 `Modeling`, 작업 폴더와 상위 폴더들의 `Modeling` 순이다. 환경 변수는 UTF-8 경로다.
3. 각 위치에서 `LowPolyKit_v숫자`를 높은 버전부터 시도한다. 지원 카탈로그 스키마는 1~3이다.
4. 카탈로그·336명 외형 할당·GLB를 함께 읽는다. v2 이상은 `validation.json`의 검사 통과를 요구하고, v3는 애니메이션 카탈로그와 몬스터 파일까지 확인한다.
5. 불완전한 패키지는 사유를 기록하고 이전 패키지를 시도한다. 선택한 패키지는 전체 검증 후 한 번에 교체한다. 실패한 재초기화는 기존 자원을 유지한다.

공용 NPC 파일 하나, 프롭 파일 하나, 몬스터 5종을 읽는다. 직군별 완성 예시 GLB 5개를 중복으로 읽지 않는다. 캐시 키는 정규화한 절대 경로이며 `shared_ptr<const Asset>`를 반환한다. 여러 인스턴스가 정점·인덱스·재질·클립을 공유하고 포즈만 독립적으로 유지한다.

신규 파일은 `ModelAssets().Load(path)`로 필요 시 읽을 수 있다. 패키지 카탈로그의 변경 반영은 재시작 또는 명시적 `Initialize` 호출로 한다. 프레임마다 폴더를 탐색하거나 GLB를 재파싱하지 않는다. 동일 경로 파일을 편집한 뒤 `Load`만 재호출하면 캐시를 반환하므로, 패키지 갱신에는 `Initialize`를 사용한다. 서비스는 게임 메인 스레드에서 사용한다.

프로젝트의 기존 빌드 후 복사 단계에 GLB와 런타임 JSON 복사를 추가했다. 실행 파일 옆 `Modeling`에 원래 하위 경로를 보존한다. `.blend`, 제작 스크립트, 프리뷰 이미지/GIF는 복사하지 않는다.

## 메시·재질 규약

- GLB의 **미터, Y 위, 정면 +Z**, 열 우선 행렬을 그대로 보존한다. Blender 좌표를 다시 변환하지 않는다. 게임 월드 단위와 미터의 비율은 향후 렌더러 연결 때 명시적으로 정한다.
- 삼각형, 인덱스, POSITION/NORMAL/TEXCOORD_0/COLOR_0, 최대 8개 본 영향(JOINTS/WEIGHTS 0·1)을 읽는다. 노멀이 없으면 생성하고 웨이트 합을 정규화한다.
- 파트는 이미 공통 원점을 기준으로 제작돼 있다. 카탈로그의 `joint_pivot`를 파트 이동으로 적용하지 않는다.
- PBR의 선형 baseColor, metallic/roughness, emissive 및 emissive strength, 알파/양면/unlit 설정을 보존한다. 이미지 바이트 또는 URI와 텍스처 참조·UV 변환도 보존하지만 이미지 디코딩·GPU 업로드는 별도 단계다. 현재 전달본은 이미지 텍스처가 없는 색상 재질이다.
- 정점·인덱스·본 범위, 유한 값, 계층 순환, 키 시간, 클립 이름·길이·이벤트 시점을 확인한다. 파일/버퍼 256MiB, JSON 16MiB 등의 제한을 둔다.
- Draco/meshopt 압축, 모프 타깃, TEXCOORD_1 이상, 삼각형 이외 토폴로지, sparse 인덱스는 명시적 오류로 처리한다. 일반 정점·애니메이션 accessor의 sparse 값은 cgltf가 전개한다. 지원하지 않는 필수 glTF 확장이 있는 파일도 거부한다.

## NPC 조립과 대응

`Npc(id, role)`는 현재 게임의 숫자 ID와 직군을 기준으로 외형을 선택한다. 일치하는 할당이 없거나 직군이 달라지면 해당 직군의 프리셋을 ID 기준으로 안정적으로 선택한다. 카탈로그의 일부 한글 이름이 이미 깨져 있으므로 에셋의 이름·마을·성향 정보로 게임 NPC의 실제 상태를 덮어쓰지 않는다.

20/21 슬롯과 -1 빈 파트를 지원한다. 투구의 헤어/머리 배제, 사제복의 골반·허벅지·정강이 배제와 신발 유지, v3 직군별 손 장비, 기사의 허리 검 중복 제거를 적용한다. `ModelInstance.nodes`만 그려야 하며, 공용 GLB의 51개 파트를 전부 그리면 안 된다.

`Player(role)`는 플레이어용 직군 프리셋을 반환한다. `Monster(index)`는 0 망자, 1 약탈자, 2 수문장, 3 변이체, 4 죽음의 잔재다. 몬스터는 체격에 맞춘 자체 바인드와 클립을 사용한다. `height_scale`을 또 곱하면 크기가 중복 적용되므로 자동 적용하지 않는다.

`Prop(propIndex)`와 `GameProp(gameKind)`는 별개다. v3의 게임 kind 1~10을 catalog `game_prop_mapping`으로 변환한다. v1·v2에 없는 게임 kind 대응은 임의로 추정하지 않고 빈 결과를 반환한다. 원본의 건물에는 콜리전·실내·LOD가 없으므로 로더가 기존 충돌 크기를 변경하지 않는다.

## 애니메이션

v3의 NPC 45개, 몬스터 79개 클립을 읽는다. 본 배열 저장 순서와 별개로 부모부터 월드 행렬을 계산한다. 스키닝 행렬은 **inverse(meshWorld) × jointWorld × inverseBind**이며 skin.joints 순서를 보존한다.

STEP, LINEAR, CUBICSPLINE을 지원한다. 회전 LINEAR는 최단 경로 SLERP, cubic은 시간 간격을 반영한 Hermite 후 정규화다. 애니메이션에 없는 채널은 바인드 포즈를 유지한다. 반복 클립은 시간을 순환하고 단발 클립은 마지막 포즈에서 멈춘다. `AnimationPlayer`는 기본 0.12초 전환과 걷기↔달리기 위상 유지 옵션을 제공한다. 같은 단발 클립을 다시 시작할 때는 `Play`의 `restart=true`를 사용한다. 스키닝 팔레트는 출력 벡터를 받는 `SkinMatrices` 오버로드로 저장 공간을 재사용할 수 있다.

방향 전환 클립은 루프가 아니며 끝의 root 회전을 유지한다. 로더는 actor의 방향을 자동으로 누적하지 않는다. 실제 연결 시 애니메이션 root 회전과 actor 회전 중 어느 한 곳에서만 방향을 적용해야 한다. NPC와 몬스터 간 단순 이름 기반 리타기팅은 하지 않는다.

`NpcAction(actionIndex)`는 19개 행동의 Prepare/Approach/Perform/Recover, 진입/이탈, 직군별 동작, 손 장비 교체 요청을 제공한다. `perform == "role_attack"`이면 `performByRole`에서 실제 클립을 선택한다. `MonsterClip(index, state)`는 몬스터 상태의 클립 이름을 제공한다. 이는 상태 머신이 사용할 메타데이터이며 현재 AI의 상태 전이를 바꾸지 않는다.

발사·타격 이벤트는 `Advance`에서 출력 벡터에 추가하는 알림이다. 프레임이 이벤트 시각을 건너뛰어도 해당 구간의 이벤트를 전달한다. 호출자는 매 프레임 벡터를 비워 사용한다. 게임플레이 피해/발사 함수를 자동 호출하지 않으며, 훈련의 `visualEventsOnly`도 전달한다. 장비 교체·사망 후 표시 유지·발사체 효과는 렌더러 및 상태 머신 연결 때 적용한다.

```cpp
// Once when creating an actor; resource stays shared.
auto instance = game.ModelAssets().Npc(npcId, role);
if (instance)
{
    Models::AnimationPlayer player(instance.asset);
    player.Play("NPC_Walk", 0.12f, true);

    // Each update; keep player as an actor member in production.
    std::vector<Models::AnimationEvent> events;
    player.Advance(deltaTime, events);

    // Each selected mesh: upload vertices/indices once; update only the palette.
    for (int meshNode : instance.nodes)
    {
        auto palette = Models::SkinMatrices(*instance.asset, player.CurrentPose(), meshNode);
    }
}
```

## 로그와 정적 검토

`[ModelAssets]`에 파일명, 메시/정점/삼각형/재질/스킨/클립 수, 로딩 시간, 패키지 선택·실패 사유, 공유 파일 수, NPC 할당 수를 기록한다. 기존 렌더러의 드로우콜 통계와는 별개이며, 아직 GPU 모델 드로우콜을 측정한 로그가 아니다.

실제 v1·v2·v3 전달 파일을 Python으로 독립적으로 읽어 검사했다. 각 336명 외형 할당, 모든 파트/프롭 이름·인덱스, 삼각형 범위, 웨이트 합, 본 팔레트 범위, 바인드 시 스키닝 행렬, 키 시각·길이·쿼터니언, 반복 클립 끝 연결, 124개 클립 카탈로그 및 19개 행동 대응 검사를 통과했다. 입력 파일 해시는 JSON 보고서에 남겼다.

프로젝트 파일 XML, 소스 정렬과 변경 공백 검사도 수행했다. **C++ 빌드 및 게임/모니터 실행은 사용자 지시에 따라 수행하지 않았다.** 에셋의 정적 검사 통과는 새 C++ 로더의 실행 검증이나 실제 화면 확인을 대신하지 않는다. 빌드 후 `[ModelAssets] ready ... schema=3 ... sharedFiles=7`과 기존 게임 동작을 확인하면 된다.
