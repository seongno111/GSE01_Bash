# 《성화의 파편》 NPC 가중치 행동 AI 설계

- 문서 버전: 0.1
- 작성일: 2026-09-28
- 목적: 스토리와 NPC의 성격을 유지하면서, 상황별 가중치와 확률로 행동을 선택하는 AI의 구현 기준을 정한다.
- 범위: 주민, 상인, 성직자, 기사, 동료, 변이자, 악마 추종자, 일반 적, 잔신, 보스.
- 상태: 설계 문서다. 아래 수치와 신규 구조는 초기 제안이며 구현 완료를 뜻하지 않는다.
- 기준: 기존 `게임_기획서_초안.txt`의 핵심 게임 규칙과 대화에서 개정한 《성화의 파편》 스토리. 세계의 기원은 개정 스토리를 따른다.

## 1. 핵심 원리

NPC는 매번 같은 행동을 반복하지 않되, 아무 행동이나 무작위로 하지 않는다.

1. 자신이 알고 있는 정보로 상황을 판단한다.
2. 현재 목적과 상태에 맞는 행동 목록을 만든다.
3. 수행할 수 없는 행동을 제거한다.
4. 남은 행동에 기본 가중치, 성격, 욕구, 관계, 위험, 임무 등의 보정을 적용한다.
5. 최종 가중치에 비례해 하나를 추첨한다.
6. 선택한 행동을 일정 시간 수행하고, 완료·실패·중단 시 다시 판단한다.

예를 들어 같은 부상자를 발견해도 마라는 치료를, 이안은 도움 요청을, 세르반은 주변 경계를 더 자주 선택한다. 치료제가 없다면 치료는 아예 후보가 되지 않는다.

이 방식은 규칙 기반의 가중치 행동 AI다. 학습 모델이나 외부 API 없이 C++에서 동작할 수 있다. AI 대화 모델은 별도로 연결하며, 행동 실행 권한은 게임 로직에 둔다.

## 2. 세계관에서 지켜야 할 규칙

### 2.1 성화와 오염

- 성화는 아우렐이 인류에게 준 축복이다.
- 바르카잔의 공격과 대파열로 성화가 흩어졌고, 악마의 저주가 엉긴 파편과 재가 오염을 퍼뜨린다.
- 성화 보유자는 오염에 저항할 수 있다. 모든 보유자가 귀환자인 것은 아니다.
- 성화의 획득 경로는 성당 수여, 우연한 결속, 계승, 약탈·거래, 잊힌 성소와의 공명 등으로 구분한다.
- 획득 경로와 파편의 세기는 성격이나 도덕성을 자동으로 결정하지 않는다.
- 죽음·오염·괴물화·정화·새벽의 성유·잔신 생성은 중앙 게임 규칙이 처리한다. 행동 AI가 임의로 바꾸지 않는다.
- 괴물의 외형만으로 적대 세력을 부여하지 않는다. 자아를 유지하는 변이자는 대화·구조·거래의 대상이 될 수 있다.

### 2.2 확률로 바꾸지 않는 서사

- 바르카잔의 지배 의도와 검은 사도들의 악행은 핵심 설정이다. 일반 행동 추첨으로 개심시키지 않는다.
- 마라가 갑자기 성화 약탈자가 되거나, 이안이 아무 계기 없이 주민을 공격하지 않는다.
- 로엔의 타락·회복, 세르반의 신념 변화 등은 사건과 관계 조건으로 분기한다. 매 판단마다 배신 확률을 굴리지 않는다.
- 보스의 단계 전환, 필수 의식, 엔딩 조건은 명시적 사건 규칙으로 처리한다. 단계 안의 전술만 확률화한다.
- 진행에 필요한 대화와 완료한 퀘스트의 보상은 대기열과 상호작용으로 제공한다. 낮은 추첨 확률 때문에 영구히 누락시키지 않는다.

## 3. 의사결정 구조

| 계층 | 역할 | 예시 |
| --- | --- | --- |
| 게임 규칙 | 가능한 일과 불가능한 일을 결정 | 사망, 정화 자격, 진영, 성역 진입 규칙 |
| 장기 목적 | 현재 추구하는 일 | 피난민 보호, 성화 운반, 파편 탈취 |
| 행동 상태 | 현재 상황의 행동 목록 선택 | 일상, 경계, 전투, 대피, 상호작용 |
| 가중치 선택 | 목록 안에서 구체 행동 선택 | 순찰, 경고, 방어, 후퇴, 구조 |
| 행동 실행 | 이동·예약·애니메이션·효과 처리 | 치료 대상에게 이동 후 치료제 소비 |

장기 목적은 사건, 일정, 명령, 퀘스트 진행으로 변경한다. 행동 상태는 아래 우선순위를 위에서부터 확인해 결정한다.

1. 사망·기절·강제 연출 등 제어 제한.
2. 확정된 긴급 위험 대응: 붕괴 구역 탈출, 허용된 범위의 즉시 회피.
3. 유효한 전투 위협 대응. 체력·사기·임무 규칙에 따라 전투 또는 대피.
4. 진행 중인 대화·거래·정화 등 상호작용.
5. 임무 수행 또는 경계.
6. 일정과 욕구에 따른 일상.

위험 여부는 감지한 정보로 판단한다. 체력 저하와 낮은 사기가 대피 상태를 유발하는 기준은 유형별로 설정한다. 예를 들어 일반 주민은 도주를, 훈련된 기사는 엄호 후 후퇴를 선택할 수 있다.

긴급 반응이라고 해도 모든 공격을 즉시 취소하는 것은 아니다. 행동마다 허용된 중단 원인을 정한다. 강제 이동·사망과 회피 가능한 위협을 구분한다.

## 4. NPC가 보유할 데이터

| 구분 | 주요 항목 | 용도 |
| --- | --- | --- |
| 식별 | 영속 NPC ID, 유형, 진영, 고향 | 저장, 관계, 난수 식별 |
| 성격 | 용기, 연민, 의무감, 탐욕, 신앙, 신중함 | 일관된 선호 |
| 신체 | 체력 비율, 피로, 허기, 부상 | 생존과 생활 행동 |
| 정신 | 공포, 사기 | 전투 지속과 대피 판단 |
| 성화 | 보유 여부, 획득 경로, 강도, 귀환자 여부 | 능력·저항·인물 반응 |
| 오염 | 실제 오염, 변이 상태, 저항 능력 | 정화 욕구와 환경 위험 |
| 관계 | 대상별 신뢰, 호감, 원한 | 도움·경계·거래 |
| 지식 | 목격 사건, 전달받은 소문, 마지막 관측 위치·시간 | 판단 가능한 정보 제한 |
| 자원 | 돈, 식량, 치료제, 성유, 사용 가능한 장비·기술 | 행동 실행 조건 |
| 목적 | 장기 목표, 담당 구역, 근무 일정, 퀘스트 역할 | 목적 보정 |
| 실행 | 현재 행동·대상·단계, 남은 시간, 쿨다운, 최근 이력 | 지속성 및 반복 억제 |
| 재현 | 난수 상태, 판단 순번, 데이터 버전 | 저장·재현·디버깅 |

성격·욕구·공포 등은 0~1, 신뢰·호감은 -1~1로 정규화한다. 원한은 0~1을 사용한다. 실제 오염은 중앙 게임 수치를 쓰고 AI 입력에서 정규화한다. 미지의 정보는 0으로 단정하지 말고 `unknown`으로 구분한다.

다른 NPC의 오염 수치나 성화 강도는 자동으로 알 수 없다. 관찰 가능한 외형, 허용된 감지 능력, 당사자의 발언으로 추정한다. 상태 변화는 실제 사건으로 갱신하며, 정화했다고 신뢰나 원한을 초기화하지 않는다.

## 5. 가중치 계산

### 5.1 실행 조건을 먼저 확인한다

다음 조건을 모두 통과한 행동만 후보가 된다.

- 현재 행동 상태와 역할에서 허용되는 행동인가?
- 필요한 기술·장비·자원을 갖고 있는가?
- 유효한 대상이나 목적지가 있는가?
- 대상에 대한 지식, 거리, 시야, 경로 조건을 충족하는가?
- 쿨다운이 끝났는가?
- 현재 진영·성역·퀘스트·서사 규칙에 위배되지 않는가?
- 대상이나 작업 장소를 예약할 수 있는가?

일반 공격의 적대 조건은 진영, 실제 공격 사건, 명시적인 스토리 규칙으로 판단한다. 낮은 신뢰나 높은 오염 수치만으로 공격 권한이 생기지 않는다.

필수 조건을 통과하지 못하면 가중치는 정확히 0이다. 아무리 긴급해도 존재하지 않는 성유를 사용하거나 접근 불가능한 부상자를 원격 치료하지 않는다.

### 5.2 계산식

```text
S(a) = clamp(
    B(a)
    + Personality(a)
    + Need(a)
    + Relation(a)
    + Situation(a)
    + Goal(a)
    - Cost(a),
    0, 100
)

W(a) = S(a) × Continuity(a) × Repetition(a)

Wmax = 현재 유효 후보의 W 최댓값
Q(a) = (W(a) / Wmax) ^ (1 / T)
P(a) = Q(a) / ΣQ
```

`Wmax > 0`일 때만 확률을 계산한다. 가중치가 0인 행동은 거듭제곱 계산에서 제외한다.

| 항목 | 초기 범위 | 의미 |
| --- | --- | --- |
| B | 0~40 | 역할별 기본 가중치 |
| Personality | -20~+20 | 성격과 행동의 적합성 |
| Need | -20~+30 | 피로·허기·회복 등 욕구 |
| Relation | -25~+25 | 대상과의 신뢰·원한 |
| Situation | -40~+40 | 위험·거리·환경·목격한 위협 |
| Goal | -20~+30 | 임무·일정과의 적합성 |
| Cost | 0~30 | 소모품·이동·노출 비용 |
| Continuity | 1 또는 1.2 | 중단 가능 시점에 현재 지속 행동을 유지할 보너스 |
| Repetition | 0.35~1 | 최근 반복 행동의 선호 감소 |
| T | 0.5~1.5 | 선택의 다양성을 조절하는 온도 |

각 보정은 해당 입력의 계수 합계를 계산한 뒤 표의 범위로 제한한다. 데이터에서 최종 보정값만 임의로 넣지 말고 입력과 계수를 명시한다.

예시로 `치료`의 성격 보정은 `clamp(20×연민 + 8×의무감 - 10×탐욕, -20, 20)`, 관계 보정은 `clamp(20×신뢰 - 15×원한, -25, 25)`로 시작할 수 있다. 이는 초기 조정값이다.

오염 회피의 상황 보정에는 감지한 지역 오염과 자신의 저항을 함께 사용한다. 용기와 저항이 높아도 실제 오염 피해는 게임 규칙대로 받는다.

- T=1: 최종 가중치에 비례한 추첨.
- T=0.5: 높은 가중치의 선택이 더 우세하다.
- T=1.5: 낮은 가중치의 행동도 비교적 자주 선택된다.
- T=0은 사용하지 않는다. 완전 결정적 선택은 별도 모드로 최고 점수 행동을 선택한다.

가중치마다 추가 난수를 넣는 방식은 초기 구현에서 사용하지 않는다. 가중치 추첨만으로 충분한 다양성을 확보하고 원인 추적을 쉽게 한다.

### 5.3 실제 확률 예시

마라가 부상자를 발견했고, 접근 가능한 대상·치료제·도움 요청 수단이 모두 있는 상황이다. T=1, 지속·반복 보정은 1이다.

| 행동 | 기본 | 성격 | 욕구 | 관계 | 상황 | 목적 | 비용 | 최종 가중치 | 확률 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 직접 치료 | 20 | 15 | 0 | 5 | 15 | 10 | 5 | 60 | 60% |
| 도움 요청 | 10 | 5 | 0 | 0 | 5 | 5 | 0 | 25 | 25% |
| 주변 경계 | 5 | 0 | 0 | 0 | 5 | 0 | 0 | 10 | 10% |
| 작업 복귀 | 10 | 0 | 0 | 0 | -10 | 5 | 0 | 5 | 5% |

치료제가 없으면 직접 치료는 제외되어 나머지 확률은 62.5%, 25%, 12.5%가 된다. 즉시 탈출해야 할 붕괴가 감지되면 이 표를 그대로 추첨하지 않고 긴급 대응으로 전환한다.

### 5.4 반복 억제와 대상 선택

- 최근 30초 안의 완료 행동 3개 중 같은 행동 유형의 횟수를 n으로 센다.
- 일반 행동의 반복 계수는 `max(0.35, 1 / (1+n))`로 시작한다.
- 순찰 지속, 대피, 필수 구조 작업은 반복 억제에서 제외할 수 있다. 예외는 행동 데이터에 표시한다.
- 동일 행동의 다른 대상도 같은 행동 유형으로 집계해 표적 교체로 반복 제한을 우회하지 않게 한다.
- 행동 유형을 먼저 추첨한 다음, 해당 행동의 유효 대상 중 긴급도·관계·거리 비용으로 대상을 정한다. 동률은 영속 ID 순으로 처리한다.
- 부상자가 10명이라고 치료 후보를 10개 만들어 치료 확률을 10배로 늘리지 않는다. 인원 증가의 영향은 상황 보정에 명시적으로 넣는다.

`seek_purification`은 방문 행동이고 `purify`는 실제 효과 행동이다. 임계점 이후 일반 정화는 후보에서 제외한다. 정화 수치, 소비량, 귀환 조건을 이 문서의 확률로 변경하지 않는다.

거래 수락, 보상 수령, 플레이어가 시작한 정화 등은 일상 추첨보다 우선하는 요청으로 처리한다. 위험이나 자격 부족으로 거절할 때는 이유를 표시한다.

## 7. 인물별 행동 성향

다음 성격 수치는 시작값이다. 서사 사건에 따른 변경만 저장하며 매번 무작위로 재설정하지 않는다.

| 인물·유형 | 용기 | 연민 | 의무감 | 탐욕 | 신앙 | 신중함 | 대표 행동 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 마라 | 0.55 | 0.95 | 0.85 | 0.10 | 0.40 | 0.80 | 수선, 치료, 배급, 구조 요청 |
| 이안 | 0.40 | 0.85 | 0.65 | 0.05 | 0.65 | 0.70 | 종 울리기, 전달, 대피 안내 |
| 세르반 | 0.90 | 0.60 | 0.95 | 0.10 | 0.90 | 0.75 | 순찰, 엄호, 호위, 경고 |
| 로엔 | 0.90 | 0.70 | 0.75 | 0.15 | 0.30 | 0.35 | 위험 지역 선행, 공격, 구조 |
| 오르델 | 0.65 | 0.60 | 0.95 | 0.15 | 0.95 | 0.95 | 성화 관리, 지원 배치, 정화 |
| 일반 피난민 | 0.25 | 0.55 | 0.40 | 0.25 | 0.50 | 0.85 | 식량 확보, 가족 보호, 대피 |
| 변이자 치료사 | 0.60 | 0.85 | 0.70 | 0.10 | 0.35 | 0.80 | 치료, 약초 수집, 위험 지역 구조 |

신앙은 선악 점수가 아니다. 성화 관리, 기도, 교단 명령에 대한 태도에 쓰고, 실제 행동의 도덕성은 목적과 사건으로 표현한다.

### 마라

- 부상자와 자원 부족을 우선 관찰한다. 직접 전투보다 구조·치료를 선호한다.
- 변이한 플레이어를 알아보고 도움받은 기록이 있으면 외형 공포보다 신뢰 보정이 강하게 작용한다.
- 신뢰가 높아도 치료제나 식량이 생겨나지는 않는다. 부족하면 도움 요청이나 공급 임무 안내를 선택한다.

### 이안

- 직접 공격·성화 약탈은 행동 목록에서 제외한다.
- 위험 시 종 울리기, 성인에게 알리기, 피난 경로 안내를 선택한다.
- 종이 파괴되면 다른 전달 수단을 찾는다. 불가능한 종 울리기를 반복하지 않는다.

### 세르반

- 적이 보호 대상에 접근하면 엄호와 차단 가중치가 증가한다.
- 임무 구역을 벗어나 추격하지 않도록 추적 한계를 적용한다.
- 플레이어의 변이를 처음 보면 경계할 수 있지만, 오염만으로 공격하지 않는다.

### 로엔

- 위험한 구조와 공격을 선호하며 일반 후퇴 가중치가 낮다.
- 죄책감·관계 사건은 장기 목적에 영향을 준다. 타락 분기가 승인된 뒤에만 변경된 행동 목록을 적용한다.
- 계승한 불씨를 무작위로 버리거나 동료에게서 빼앗지 않는다.

### 악역과 적

| 대상 | 고정 목적 | 가중치로 선택할 수 있는 행동 | 금지되는 임의 변화 |
| --- | --- | --- | --- |
| 바르카잔 | 지배 의식 완성 | 공격 패턴, 위치 이동, 허용된 소환 | 무작위 항복·개심 |
| 모르가트 | 성소 파괴·구조 방해 | 통로 봉쇄, 추격, 공격 | 피난민에게 무작위 친절 |
| 에드란 | 오염 의식 확산 | 의식 지속, 경호 요청, 도주 | 실제 규칙 없이 정화 보상 제공 |
| 칼드레 | 성화 강탈 | 보유자 추적, 방어, 강공격 | 조건 없는 파편 획득 |
| 잔신 | 원래 불씨 추적 | 접근, 계승 기술, 거리 조절 | 대화 추첨에 의한 원한 삭제 |

잔신은 사망 스냅샷에 있는 기술과 장비 특성만 후보로 사용한다. 현재 구현에 없는 기술 계승은 후속 확장 항목이다. 비활성 지역에서 플레이어의 현재 좌표를 계속 추적하지 않는다.

## 8. 행동 지속과 중단

### 8.1 판단 주기

| 상황 | 초기 판단 간격 |
| --- | --- |
| 근거리 전투 | 0.25~0.5초 |
| 경계·호위 | 0.5~1초 |
| 근거리 일상 | 2~4초 |
| 먼 활성 NPC | 5~15초 |
| 비활성 청크 | 개별 판단 중지, 제한된 요약 갱신 |

역할별 간격을 정하고 NPC ID에 따른 고정 시간차로 판단을 분산한다. 렌더링 프레임마다 재추첨하지 않는다. 이동·충돌·애니메이션은 기존 갱신 주기로 계속 실행한다.

### 8.2 실행 단계

행동은 `준비 → 접근 → 수행 → 회복 → 완료` 중 필요한 단계를 사용한다. 실행 결과는 `진행 중 / 성공 / 실패 / 중단`으로 구분한다.

- 일상 행동은 최소 2~5초 지속하도록 시작한다. 완료 조건이 먼저 충족되면 종료한다.
- 공격 예고·타격·회복 중에는 일반 재추첨으로 행동을 취소하지 않는다.
- 대피는 안전 지점에 도착하거나 위험이 일정 시간 사라져야 끝난다. 제안 안정 시간은 3초다.
- 계속 유지할 수 있는 순찰·경계는 중단 가능 시점에서만 유지 보너스를 계산한다.
- 일회성 공격의 완료 후 재공격에는 유지 보너스를 붙이지 않는다.
- 강제 중단 시 자원 예약, 대상 예약, 효과 발생 여부를 정리한다.

### 8.3 실패와 대체 행동

- 경로 실패: 해당 행동·대상을 3초간 제외하고 다른 경로나 대상을 찾는다.
- 예약 경쟁 실패: 이번 판단에서 실패 쌍을 제외하고 최대 1회 대체를 시도한다.
- 자원 부족: 해당 행동을 제외하고 자원 확보·도움 요청을 평가한다.
- 대상 소실: 마지막 관측 위치까지만 수색한다. 실제 현재 위치를 몰래 읽지 않는다.
- 모든 가중치가 0: 결정적 대체 규칙을 사용한다. 즉각적인 위험과 유효 탈출 경로가 있으면 대피, 없으면 방어·도움 요청 중 가능한 것, 평상시에는 안전한 대기 순이다.
- 어떤 행동도 불가능하면 현재 위치에서 효과 없는 제한 대기를 수행하고 다음 판단을 예약한다. 같은 프레임에 무한 재시도하지 않는다.

## 9. 구현 의사코드

```text
UpdateNPC(dt):
    중앙 규칙의 사망·기절·강제 상태를 먼저 반영한다
    허용된 주기로 감각과 지식을 갱신한다
    긴급 사건이 있고 현재 행동이 해당 사건으로 중단 가능하면:
        현재 행동의 예약과 미확정 효과를 정리한다
        결정적 긴급 대응을 시작한다

    현재 행동의 이동·수행·회복을 갱신한다
    실행 효과는 별도 게임 규칙에서 최종 검증한다
    현재 행동이 진행 중이고 중단 가능 시점이 아니면 반환한다
    일반 판단 시간이 아니고 새 판단 사건도 없으면 반환한다

    현재 목적과 지식으로 행동 상태를 결정한다
    아직 처리되지 않은 필수 요청이 있고 수행 가능하면:
        요청 행동을 검증·예약 후 시작한다
        반환한다

    후보 = 현재 역할·상태에서 허용한 행동 유형 목록
    각 유형마다 유효 대상 목록을 작성한다
    대상이 없거나 조건 불충족인 행동은 제외한다
    대상별 점수를 평가해 유형별 대표 대상을 고른다
    유형과 대표 대상에 대해 최종 가중치를 계산한다

    양수 가중치가 없으면 결정적 대체 행동을 시작한다
    그렇지 않으면:
        행동 ID 순으로 정렬한다
        NPC 전용 난수에서 u를 [0, 1) 범위로 1회 얻는다
        r = u × Q의 합계
        누적 Q가 r보다 처음 커지는 행동을 고른다
        실행 직전 조건을 재검증하고 대상을 예약한다
        성공하면 행동 인스턴스를 생성하고 시작한다
        실패하면 제한된 대체 처리 후 다음 판단을 예약한다

    판단 순번, 후보 점수, 선택 이유를 기록한다
```

부동소수 오차로 누적 비교가 선택을 만들지 못하면 마지막 양수 후보를 사용한다. NaN·무한대·잘못된 음수 설정은 로딩 또는 평가 단계에서 오류로 기록하고 해당 후보를 제외한다.

## 11. 여러 NPC의 협력과 실행 안전성

- 부상자, 작업대, 경계 지점에는 예약 소유자와 만료 시간을 둔다.
- 치료 두 명이 같은 아이템이나 대상을 동시에 소비하지 않도록 실제 효과 적용을 원자적으로 검증한다.
- 예약한 NPC가 죽거나 청크를 떠나면 해제한다. 저장된 예약은 로딩 시 재검증한다.
- 경보는 사건 ID, 발신자, 위치, 전달 범위를 가진다. 다른 지역 NPC가 자동으로 아는 전역 플래그로 만들지 않는다.
- 집단에서는 지휘관이 역할을 배정하고 각 NPC가 역할 내 행동을 선택할 수 있다. 모두가 같은 적에게 몰리거나 전원이 치료에만 나서는 일을 줄인다.
- 민간인의 전투 행동은 명시된 자위·방어 능력 범위로 제한한다.
- 효과에는 고유 실행 ID와 적용 완료 표시를 붙여 저장·재개·재요청에 따른 중복 치료, 보상, 성화 이전을 방지한다.

## 12. AI 대화와 행동의 연결

대화 모델에는 NPC 성격, 실제로 아는 사건, 플레이어와의 관계, 현재 목표, 허용된 상호작용 목록을 전달한다.

모델의 역할은 표현과 제한된 행동 요청이다. `정화를 돕겠다고 말하기`와 `실제 정화를 수행하기`는 분리한다.

```text
플레이어 요청
→ 대화 모델 또는 기본 선택지의 의도 해석
→ 허용된 행동 ID와 대상 검사
→ 중앙 게임 규칙에서 자격·자원·상태 확인
→ 상호작용 요청 등록
→ 행동 실행과 결과 확정
→ 확정 결과에 맞춘 대사
```

- 자유 대화로 가중치, 진영, 기억, 아이템, 퀘스트 완료 상태를 직접 수정하지 않는다.
- 약속은 실행 가능한 범위에서만 확정한다. 실패 시 이유를 설명한다.
- NPC가 목격하지 않은 배신이나 도움을 대화 모델이 만들어 내지 않게 한다.
- 일반 대화 도중에는 무작위 작업 복귀로 갑자기 자리를 뜨지 않는다. 위험이 발생하면 대화를 중단하고 이를 표시한다.
- 대화 서비스가 느리거나 실패해도 전투와 행동 AI는 계속 작동한다. 필수 상호작용에는 기본 대사·선택지를 제공한다.

## 13. 확장 월드·저장·재현

- 근처 NPC만 상세 판단한다. 화면 밖이라도 실제 전투·호위에 참여하면 상세 상태를 유지한다.
- 먼 NPC의 요약 갱신은 일정, 휴식, 명시된 생산 정도로 제한한다. 필수 인물 사망, 성화 탈취, 주요 분기, 잔신 처치를 임의 추첨으로 확정하지 않는다.
- 이미 시작한 공격·치료 등 중요한 효과는 완료하거나 정지 상태로 저장한다. 청크를 나갔다고 무료 완료하지 않는다.
- NPC ID, 관계, 사실 기억, 목표, 실행 단계, 잔여 시간, 쿨다운, 반복 이력, 미처리 사건·요청, 난수 상태, 데이터 버전을 저장한다.
- 대상과 예약은 로딩 시 존재·거리·자원을 다시 확인한다. 불가능하면 실패 절차로 복구한다.
- NPC별 난수 흐름을 사용한다. 다른 NPC 생성이나 렌더링 효과의 난수 소비가 선택을 바꾸지 않게 한다.
- 월드 시드·NPC ID·명시적인 고정 해시로 초기 난수를 만든다. 실행마다 달라질 수 있는 기본 문자열 해시는 피한다.
- 같은 저장과 같은 입력을 재현하려면 고정 시뮬레이션 시간, 사건 처리 순서, 후보 정렬, 난수 알고리즘과 상태를 함께 고정해야 한다.
- 플랫폼 간 완전 동일 재현이 필요하면 점수의 고정소수점화와 난수→구간 변환 규칙을 별도로 확정한다. 기본 난수 시드만으로 이를 보장하지 않는다.
- 수치 변경 시 데이터 버전을 기록한다. 구버전 저장의 행동 ID가 없어지면 안전한 대체 행동으로 이관한다.

## 14. 현재 프로젝트에 적용하는 순서

2026-09-28 확인한 코드 기준:

- `SimpleGame/EnemyActor.cpp`: 거리·성역·귀환 범위에 따른 이동, 공격 예고·회복, 상위 적의 특수 공격이 구현되어 있다.
- `SimpleGame/EchoActor.cpp`: 플레이어와의 거리와 성역 여부에 따른 추적·공격이 구현되어 있다.
- `SimpleGame/GameActors.h`: 적과 잔신의 상태 필드가 선언되어 있다.
- `SimpleGame/GameRules.h`: 성역 판정과 변이 임계값 등 공통 규칙이 있다.

기존 코드의 동작과 이 문서의 목표 설계를 구분한다. 특히 잔신의 전체 장비·기술 계승과 일반 주민 생활 AI는 이번 확인에서 구현을 확인하지 않았다.

### 1단계: 일반 적 한 종류

접근, 일반 공격, 거리 조절, 담당 구역 복귀만 후보로 만든다. 기존 성역 판정·추적 범위·공격 예고·피해 처리는 유지하고, 다음 행동을 고르는 지점만 교체한다. 기존 공격이 즉시 명중하도록 바뀌지 않게 한다.

### 2단계: 주민과 기사

주민은 작업·휴식·도움 요청·대피, 기사는 순찰·경고·호위·전투를 적용한다. 상태별 후보 목록과 성격 차이를 검증한다.

### 3단계: 관계·오염·정화

알고 있는 사건에 따른 신뢰, 외형 경계, 성화 저항, 정화 방문과 성유 사용을 연결한다. 오염과 적대 진영을 분리한다.

### 4단계: 주요 인물·집단·잔신

인물별 프로필, 임무 배정, 예약, 경보 전달을 추가한다. 잔신은 실제 저장된 기술만 후보로 만들고, 보스는 단계별 허용 전술을 사용한다.

### 5단계: 저장·원거리 처리·대화

행동과 난수를 저장하고 청크 로딩에 연결한다. 확정 사건을 대화 모델에 제공하고 검증된 요청만 실행한다.

제안 구성 요소는 `NpcBrain`(판단), `NpcKnowledge`(지식), `ActionDefinition`(행동 데이터), `ActionInstance`(실행 상태), `ActionExecutor`(실행), `NpcProfile`(성격·역할), `ReservationService`(예약)다. 파일 분리는 프로젝트 규모에 맞춰 결정한다. C++ 예제나 구현을 추가할 때는 `CODE_STYLE.md`를 따른다.

## 15. 검증과 조정 기준

이 절은 구현 후의 검증 계획이다. 본 문서 작성으로 아래 테스트를 실행했다는 의미는 아니다.

| 상황 | 기대 결과 |
| --- | --- |
| 고정 가중치 60/25/10/5, T=1, 반복 보정 해제 | 독립 선택 10,000회에서 이론 확률과 대체로 일치. 개발 점검 기준 각 ±2%p |
| 후보가 하나 | 항상 해당 행동 선택 |
| 전부 0, 전부 조건 불충족 | 대체 행동, NaN·무한 재추첨 없음 |
| 치료제 없음, 경로 차단 | 치료 시작·아이템 소비 없음 |
| 치료사 2명과 부상자 1명 | 예약 정책대로 실행, 중복 소비·효과 없음 |
| 공격 예고 도중 일반 판단 주기 도래 | 기존 공격·회복 유지, 예고 취소로 플레이어를 속이지 않음 |
| 변이했지만 우호적인 플레이어 | 경계 가능, 오염만으로 공격하지 않음 |
| 정화 후 재방문 | 외형 반응은 변화, 과거 배신의 원한은 유지 |
| 알려지지 않은 먼 지역 사건 | 정보 전달 전 반응하지 않음 |
| 조건을 만족한 퀘스트 보상 요청 | 무작위 일상 선택에 묻히지 않고 처리 |
| 효과 확정 직후 저장·불러오기 | 아이템·치료·보상이 다시 적용되지 않음 |
| 같은 저장·입력·버전으로 재실행 | 동일한 선택 순서 재현 |
| 보스와 로엔의 분기 | 허용된 단계·사건 외 임의 개심·배신 없음 |
| 원거리 청크 반복 로드 | 인물 복제·예약 누수·보상 재생성 없음 |

디버그 표시에는 현재 상태·목표·지식 출처, 행동별 탈락 사유, 기본값과 각 보정, 최종 확률, 추첨값, 선택 행동·대상, 다음 판단 시간, 예약·쿨다운을 포함한다. 개발 로그는 최근 판단을 제한된 버퍼에 보관해 무한 월드에서 무제한 누적되지 않게 한다.

수치 조정은 먼저 실행 조건과 목표를 확인하고, 그다음 기본값·보정·온도를 순서대로 조절한다. 이상한 행동을 전부 낮은 확률로 감추지 않는다.

## 16. 초기 완료 기준

- 같은 상황에서 둘 이상의 합리적인 행동이 발생한다.
- 같은 인물은 반복 관찰 시 일관된 성격을 보인다.
- 불가능한 행동, 서사 위반, 프레임별 행동 흔들림이 발생하지 않는다.
- 성화·오염·정화·잔신 규칙이 확률 선택 때문에 변하지 않는다.
- 관계와 사건이 실제 선택과 대화에 반영된다.
- 선택 이유를 가중치 로그로 설명하고 저장 상태에서 재현할 수 있다.

**핵심 기준: 무엇을 할 수 있는지는 규칙이 정하고, 그중 무엇을 할지는 성격과 상황을 반영한 가중치가 정한다.**
