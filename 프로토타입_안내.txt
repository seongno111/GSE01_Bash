1. 이번 작업의 범위
  현재 C++ / OpenGL 프로젝트를 2.5D 아이소메트릭 장면으로 확장했다.
  화면에 표시하는 The Last Ember는 시연용 가제이며 정식 게임명이 아니다.
  성소의 불빛, 무너진 성당, 황무지, 오염 웅덩이, 고사목과 묘비를
  외부 이미지 없이 색이 있는 도형으로 표현한다.
  최종 그래픽 자산이나 최종 게임 규칙을 확정하는 단계는 아니다.

2. 사용자 빌드·실행
  SimpleGame.sln을 Visual Studio에서 연다.
  기존에 구성된 Debug / x64를 우선 사용한다.
  프로젝트는 v145 도구 집합과 Windows SDK, C++17을 사용한다.
  그래픽 드라이버는 OpenGL 3.3 core context를 지원해야 한다.
  빌드 후 셰이더와 런타임 DLL을 출력 폴더에 복사하는 작업을 추가했다.
  기존 프로젝트의 DLL을 Dependencies 폴더에도 복사하여 배포 원본으로 두었다.
  실행은 Visual Studio 또는 출력 폴더의 SimpleGame.exe를 사용한다.
  권장 첫 화면 크기는 기본값인 1280 x 800이다.
  대사와 화면 안내는 한글이다. 특별 아이템은 '성물', ECHO는 '잔재'로
  표시한다. 명칭은 시연용이며 정식 명칭 확정은 아니다.
  Windows의 맑은 고딕을 이용해 글자를 그린다. 별도 글꼴 파일은 배포하지 않는다.
  UTF-8 문자열을 유니코드로 변환하고 글자 크기별 래스터 정보를 캐시한다.

  사용자 요청에 따라 에이전트는 빌드·실행·화면 결과 검증을 하지 않았다.
  컴파일 성공 및 실제 화면 상태는 아직 확인되지 않았다.

3. 조작
  WASD  : 화면 기준 상하좌우 이동 (대각 이동 가능)
  SPACE : 근거리 공격, 연속 공격은 키를 다시 눌러 사용
  E     : 가까운 성소에서 회복·정화
  R     : 괴물 상태에서 시연용 특별 아이템 사용
  K     : 사망 시뮬레이션 (개발 확인용, 정식 조작 아님)
  G     : 청크 경계와 현재 청크 정보 표시/숨기기
  + / - : 확대/축소 (+는 = 키로도 가능)
  H     : 조작 안내 표시/숨기기
  ESC   : 종료
  P / B / V / N : 전체 후처리 / 블룸 / 비네트 / 가장자리 블러 전환
  [ / ] : 노출 조절, 0 : 후처리 기본값 복원
  후처리 구성과 조정 방법은 후처리_안내.txt를 참고한다.

4. 첫 장면과 확인 순서
  처음에는 성소의 남쪽 도로 근처에서 시작한다.
  화면 위쪽 성당 앞에 불이 타고 있는 제단이 있다.
  WASD로 이동하며 카메라 추적, 도형의 앞뒤 가림,
  성당·제단·나무·돌 주변 충돌을 확인할 수 있다.
  G를 켜고 도로를 따라 이동하면 새 지형이 이어지는 것을 볼 수 있다.
  청크는 시드와 좌표로 재생성하며 먼 청크는 메모리에서 제거한다.

  오염 시연 예시:
    1) K를 한 번 누르면 오염 25와 강화된 공격력이 표시된다.
    2) 제단 가까이 이동해 E를 누르면 오염이 0으로 돌아간다.
    3) K를 네 번 눌러 오염 100이 되면 뿔과 변이 외형이 나타난다.
    4) 이 상태에서는 E로 정화할 수 없다.
    5) K를 한 번 더 누르면 사망 위치에 ECHO 몬스터가 남는다.
    6) ECHO는 일정 거리 안에서 추적하고 근접하면 공격한다.
       SPACE로 공격하거나 성소 근처로 피신할 수 있다.
    7) R로 인간 상태로 돌아와도 이미 생긴 ECHO는 남는다.

5. 이번 시연을 위해 임시로 정한 규칙
  아래 값은 기획 확정이 아니라 화면과 상태 변화 확인을 위한 설정이다.
  - 사망당 오염 +25, 괴물화 임계값 100, 최대 오염 150
  - 공격 피해 24 + 오염 x 0.3
  - 사망 직전 이미 괴물일 때 ECHO 생성
    임계점을 처음 넘게 만든 사망에서는 아직 ECHO를 생성하지 않음
  - 사망 후 오염을 유지하고 가까운 성소 인근에서 체력 100으로 복귀
  - ECHO는 사망 당시 변이 단계와 오염 기반 전투 능력을 복사
    장비·기술 시스템이 없으므로 해당 정보의 계승은 아직 없음
  - ECHO의 추적 거리는 12타일, 성소 보호 반경은 2.8타일
  - 사망 직후 4초, 피격 직후 1초간 추가 피해 방지
  - 일반 정화와 특별 아이템 사용은 오염을 0으로 돌림
  - 특별 아이템은 실행할 때 하나 지급, 이번 시연에는 추가 획득 경로 없음
  - ECHO를 처치하면 흔적을 남기며 보상은 지급하지 않음

6. 기술 구성
  Renderer.h / Renderer.cpp
    화면 픽셀 좌표의 삼각형 배치 렌더러.
    VAO/VBO, 정점 색상, 알파 혼합, 간단한 글꼴,
    도형과 부드러운 발광 그라데이션을 지원한다.
    발광 색을 HDR 장면에 기록하고 후처리 블룸으로 빛 번짐을 합성한다.
    물리 기반 동적 조명은 아니다.

  Prototype.h / Prototype.cpp
    카메라, 입력 상태, 8 x 8 타일 청크 캐시,
    고정 시드 지형, 물체 배치와 간단한 충돌,
    성당·제단·캐릭터 도형, 깊이 순서 정렬,
    오염 시연과 실행 중 ECHO 정보를 관리한다.

  SimpleGame.cpp
    OpenGL 3.3 초기화, 타이머 업데이트, 창 크기 변경,
    키 누름/해제와 종료 시 GPU 자원 정리를 담당한다.

  Shaders/SolidRect.vs / SolidRect.fs
    배치 정점의 픽셀 좌표를 화면 좌표로 바꾸고 정점 색상을 출력한다.

7. 현재 한계와 후속 개발
  - AI 대화, NPC 관계, 퀘스트, 장비, 정식 전투는 미구현이다.
  - 저장 파일을 만들지 않는다. 오염·아이템·ECHO는 종료하면 초기화된다.
  - ECHO는 실행 중 멀리 이동해도 기록을 유지하지만 전체 기록 수의
    장기 저장·성능 대책은 아직 없다.
  - 지형 생성은 작고 단순한 동기식 처리다. 비동기 스트리밍은 후속 과제다.
  - 지형에는 고정 경계를 두지 않았지만 위치는 현재 double이고,
    청크 키는 64비트 정수다. 본격적인 장거리 월드는
    청크 좌표와 내부 좌표를 분리하는 방식으로 추가 정비해야 한다.
  - 성소·성당은 32타일 간격으로 반복하는 시연용 템플릿이다.
    지역 역사나 도로망을 고려한 콘텐츠 생성은 아직 없다.
  - 충돌은 단순한 원형 근사, ECHO 이동은 직접 추적과 축별 미끄러짐이다.
    복잡한 장애물 뒤의 길 찾기는 아직 지원하지 않는다.
  - 큰 성당을 하나의 깊이 기준으로 그리므로 건물 측면에서 정교한
    가림 처리가 필요할 수 있다. 벽 분할이나 깊이 정보 도입이 후속 과제다.
  - 아주 작은 창에서는 고정 크기 UI가 겹칠 수 있다.
  - 이미지·음향 자산은 아직 포함하지 않았다.
