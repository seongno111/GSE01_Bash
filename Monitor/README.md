# NPC 로컬 모니터링

게임의 상태를 1초 간격으로 JSON 파일에 내보내고, 로컬 HTTP 서버를 통해 HTML 화면이 JSON 메시지를 수신한다. 게임 상태를 변경하는 기능은 없다. 외부 서비스, npm 패키지, 인터넷 접속 없이 동작하도록 작성했다.

## 실행

1. 사용자가 게임을 새로 빌드하고 실행한다. 기존 실행 파일에는 내보내기 코드가 없으므로 재빌드가 필요하다.
2. Node.js 18 이상이 설치되어 있어야 한다. 현재 작업 PC에서는 `C:\Program Files\nodejs\node.exe`를 확인했다.
3. `C:\GameSoftWare\Monitor\Start-Monitor.cmd`를 실행한다.
4. 브라우저에서 **http://127.0.0.1:8765**로 접속한다.
5. 서버 종료는 콘솔에서 Ctrl+C를 누른다. 게임과 별도로 종료할 수 있다.

HTML을 파일 탐색기에서 직접 열면 자동 수신하지 않는다. 브라우저의 로컬 파일 접근 제약을 피하기 위해 위 HTTP 주소를 사용한다. 서버는 127.0.0.1에만 바인딩한다.

콘솔에서 직접 실행할 수도 있다.

```powershell
node C:\GameSoftWare\Monitor\server.mjs
```

다른 빌드 출력 폴더 또는 여러 게임 인스턴스를 사용하는 경우 JSON 경로를 명시한다.

```powershell
node C:\GameSoftWare\Monitor\server.mjs --snapshot "C:\GameSoftWare\x64\Release\NpcAI\monitor.json" --port 8765
```

기본값은 저장소의 `x64/Release`, `x64/Debug`, `Release`, `Debug`와 `SimpleGame` 아래 같은 출력 폴더를 검색하여 가장 최근 수정된 `NpcAI/monitor.json`을 읽는다. 포트가 사용 중이면 `--port 8766`처럼 변경하고 브라우저 주소도 맞춘다.

## 화면 구성

- 전체: 생존/사망 NPC, 활성/사망/비활성 몬스터, 전투·대피 NPC, 활성 변이 잔재.
- 마을: 소속 주민의 생존/등록 수, 현재 체류 NPC, 전투·광폭 인원, 영역 내 몬스터, 평균 체력·오염, 주민 금화, 금고와 시장 재고.
- 활동 지도: NPC·몬스터 위치와 마을 경계. 선택한 NPC의 목적지를 점선으로 표시한다. 게임 화면을 재현하는 지형도가 아니라 월드 좌표를 위에서 보는 상태 지도다.
- NPC: 이름·직업·위치·상태·생명력·오염·금화·활동·단계·이동 거리·완료/실패 횟수. 위치/직업/생존 여부/이름으로 필터링한다.
- 이름 클릭: 무기·목표·목적지·대상·성력·무력·지혜·허기·피로·사기·재고·최근 판단 후보의 확률과 제외 이유.
- 최근 사건과 몬스터 목록: 보스, 변이 잔재도 포함한다.

현재 **6개 마을, 마을당 초기 56명(총 336명)**이 등록된다. 기존 성당 마을에 새벽 수도촌·철벽 주둔촌·황금 장터·잿빛 탐구촌·검은 이빨 소굴을 추가했다. 각 카드에 공동체 성향(`culture`)과 중심 좌표(`center`)를 표시한다. 위치·인구·시장 재고·분위기·사건은 마을별로 집계한다.

NPC의 `homeVillageId`는 생성 시 지정한 소속이며 외출해도 바뀌지 않는다. `currentVillageId`와 사건의 `villageId`는 실제 위치에 따른다. 마을 밖은 null이다. 멀리 떨어진 주민도 실제 이동·생활·소문 전파를 계속한다. 마을 좌표와 상세 구현은 [다중 마을 구현 기록](../doc/NPC_AI_다중마을_구현.md)을 참고한다.

## 집계 기준

범위는 현재 게임의 컬렉션에 등록된 Actor다. 아직 생성하지 않은 무한 월드의 인구나 몬스터 수를 추정하지 않는다.

- NPC 등록 수에는 사망한 주민도 포함한다. 생존은 `vitals.alive` 기준이다.
- 마을의 소속 주민 수는 초기 거점 기준이므로 현재 원정을 나간 주민도 포함한다.
- 체류 인원은 현재 영역 안에 있는 생존·활성 NPC만 센다. 마을 필터 역시 현재 위치 기준이다.
- 평균 체력·오염과 주민 금화는 살아 있는 소속 주민 기준이다. 대상 주민이 없으면 평균값은 `null`이고 화면은 `—`로 표시한다.
- 몬스터는 현재 적 컬렉션과 변이 잔재 컬렉션을 매번 읽는다. 이후 추가된 적도 집계한다.
- 활성: 생존하고 Actor가 활성화됨. 사망: Actor가 활성화되어 있으나 사망 상태. 비활성: Actor가 비활성화됨. 세 분류는 겹치지 않는다. 아직 해금되지 않은 보스는 비활성이다.
- 변이 잔재 수는 몬스터 수에 이미 포함된 부분집합이다. 광폭화한 NPC는 NPC 수로 유지한다.
- 마을의 위험 표시는 영역 내 전투·대피 NPC, 광폭 NPC, 활성 몬스터 중 하나라도 존재하면 켜지는 간단한 진단 기준이다.

## JSON 수신 규격

```text
게임 NpcWorld → NpcAI/monitor.json → localhost 서버 → GET /api/snapshot → HTML
```

게임은 실제 경과 시간 기준 최대 초당 한 번, 게임 업데이트 스레드에서 UTF-8 JSON을 작성한다. 임시 파일을 닫고 교체하여 중간까지 작성된 메시지가 노출되지 않도록 한다. 큰 파일이 계속 쌓이지 않으며 최신 상태만 남긴다. 수천 NPC 규모에서는 직렬화·디스크 쓰기 비용을 실측한 뒤 별도 스레드로 복사본을 전달하는 구조를 검토할 수 있다. 기존 `latest.log`는 그대로 유지한다.

브라우저는 요청이 끝난 뒤 1초 후 다음 메시지를 받는다. 지연 중 중복 요청을 쌓지 않으며 4초 제한시간을 사용한다. 서버와 페이지 모두 캐시하지 않는다.

HTTP 응답의 최상위 필드:

| 필드 | 의미 |
| --- | --- |
| `status` | `live`, `stale`, `waiting`; 읽기/형식 오류는 HTTP 503과 `error` |
| `ageSeconds` | 스냅샷 생성 후 경과 시간 |
| `source` | 실제 읽은 JSON 파일 경로 |
| `snapshot` | 아래의 게임 메시지. 대기 상태는 null |
| `message` | 대기·오류 설명 |

게임 메시지:

| 필드 | 형식 / 의미 |
| --- | --- |
| `schemaVersion` | 숫자 4 (서버와 HTML은 기존 1·2·3도 수신) |
| `type` | `world.snapshot` |
| `sessionId` | 실행 시각과 프로세스 ID를 조합한 문자열 |
| `sequence` | 내보내기 시도마다 증가하는 순번 |
| `generatedAtUnixMs` | UTC Unix epoch 밀리초 |
| `simulationTime` | 게임 시뮬레이션 초 |
| `worldSeed` | 정밀도 손실을 피하기 위한 문자열 |
| `scope` | 관측 범위 설명 |
| `totals` | 전체 NPC·몬스터 상태별 수량 |
| `villages` | 마을 ID·이름·경계·인구·위험·경제 집계 배열 |
| `npcs` | 주민별 상태·실행·진단 데이터 배열 |
| `monsters` | 몬스터별 ID·종류·활성/생존·체력·위치 배열 |
| `events` | 시간·종류·행위자·대상·장소·출처를 가진 사건 객체 배열, 최대 2048개 |
| `recentMessages` | 기존 게임 HUD의 최근 안내 문장 배열 |
| `eventCounts` | 현재 세션의 유형별 누적 발생 수 배열 |
| `eventRetention` | 상세 사건 보관 한도, 첫 ID, 다음 ID |

NPC ID와 행동 대상 ID는 게임의 NPC Entity ID를 문자열로 보낸다. 몬스터 목록 ID는 `actor-<ActorId>` 형태이며 NPC 행동 대상의 Entity ID와 다른 식별자다. `position/home/destination`은 `{x, y}` 객체다. 후보 `probability`는 0~1 확률이며 화면에서 백분율로 바꾼다. 비정상 실수는 유효한 JSON을 유지하도록 `null`로 내보낸다. 문자열의 따옴표·역슬래시·제어문자는 이스케이프한다.

## 마을 분위기와 전체 성향

NPC의 성향 점수는 다음 진단식으로 계산한다. 게임의 공격 대상 결정에는 이 점수를 사용하지 않는다.

```text
기본 = 100 × (0.55 × 연민 + 0.45 × 의무 - 0.45 × 탐욕 - 0.65 × 약탈 성향)
행동 보정 = min(20, 돌봄·토벌 횟수 × 4) - min(50, 살인·약탈 횟수 × 10)
성향 점수 = clamp(기본 + 행동 보정, -100, 100)
```

30 이상은 선한 성향, -30 이하는 악한 성향, 나머지는 중립이다. 직업명이나 타인의 숨겨진 오염만으로 분류하지 않는다. 선악은 프로젝트의 관찰용 수치이며 보편적 윤리 판단을 의미하지 않는다. 치료·축복·토벌을 돌봄으로, 불법 살인·실제 금화 약탈을 폭력으로 센다. 최초 불법 공격의 행위자·피해자 조합을 유지하여 피해자가 반격한다는 이유로 공격자의 이후 살해가 정당방위로 바뀌지 않게 했다.

`npcs[].alignment`에는 label, score, careEvents, violentEvents가 있다. `personality`에는 계산에 사용한 성격 수치가 있다. 마을의 `alignment`에는 현재 생존·활성 체류 주민의 good/neutral/evil 인원과 averageScore가 있다. 소속 주민이 원정 중이면 해당 마을의 현재 성향 분포에서 제외된다.

분위기는 다음 순서로 평가한다.

1. 활성 몬스터·전투/대피·광폭 주민이 있으면 **전투와 위협**.
2. 최근 60초에 마을 영역 안에서 살인·사망·인간 격퇴가 발생하면 **불안과 애도**.
3. 최근 약탈이 있거나 체류 주민의 평균 사기가 40% 미만이면 **긴장과 공포**.
4. 체류 주민이 없으면 **적막**.
5. 악한 성향이 선한 성향보다 많으면 **약탈과 불신**.
6. 선한 성향이 악한 성향보다 많고 체류 인원의 절반 이상이면 **신뢰와 안정**.
7. 나머지는 **다양한 성향이 공존**.

최근 사건은 위치 기준이고 분위기는 관측 시점의 진단이다. 보관량 2048개 때문에 최근 60초 기록 일부가 잘리면 `recentEvents.windowComplete=false`를 보내고 화면에 일부 기록이라고 표시한다. 세션 전체 누적 `eventCounts`는 상세 기록 제거로 감소하지 않는다.

## 살인·소문·토벌 모니터링

사건 표는 종류·장소·행위자·대상·사건 ID로 필터링한다. 원본 사건이 아직 보관되어 있으면 소문의 출처 링크로 이동할 수 있다. 사건을 문장에 대한 추측으로 분류하지 않고 실제 효과가 적용된 코드에서 기록한다.

| type | 기록 시점 |
| --- | --- |
| murder | 불법 공격으로 NPC 또는 플레이어가 사망 |
| kill | 인간의 적대 공격에 대응한 NPC 격퇴 |
| death | 공격자를 특정하지 못한 NPC 사망 또는 불법 살인이 아닌 플레이어 사망 |
| hunt | NPC·플레이어가 몬스터/변이 잔재를 처치 |
| raid | 피해자의 금화를 실제로 이전, 이전량이 0이면 기록하지 않음 |
| rumor | 사건을 알고 있는 NPC가 모르는 NPC에게 실제 전달 |
| heal / blessing / trade / frenzy | 해당 효과가 실제 적용된 순간 |

각 사건은 문자열 `id`, 시뮬레이션 초 `time`, `type`, `text`, `position`, `villageId`, `actorId/actorName`, `subjectId/subjectName`, `sourceEventId`, `knowers`를 갖는다. 참가자 식별자는 `actor-<ActorId>`이며 NPC JSON의 새 `actorId`와 대응한다. 사망해도 이름과 사건 당시 위치가 보존된다. 원인 식별자가 없는 기존 몬스터 공격은 행위자 미상으로 표시한다. 플레이어 사망은 기존 부활 처리 직전에 한 번 기록한다.

소문은 3초마다 평시 NPC 간 거리 2.5 이내와 실제 시야를 검사한다. 직접 본 사건이나 전달받아 알게 된 사건 중 최근 120초·최근 탐색 64건을 대상으로 한다. 한 NPC는 한 주기당 최대 하나의 소문을 한 명에게 전한다. 원본 사건의 knowers에 수신자를 추가하여 같은 사건을 같은 NPC에게 반복 전하지 않는다. 원본을 삭제한 뒤에는 그 사건의 새 전달을 시작하지 않는다.

소문은 실제 사건을 전달하는 첫 구현이다. 거짓 소문 생성, 신뢰도 추정, 소문에 따른 법 집행·자동 적대는 포함하지 않는다. 사건 기록은 세션 동안만 유지되며 게임 재시작 시 초기화한다. 최신 JSON은 저장/복원용 파일이나 영구 사건 아카이브가 아니다.

## 끊김과 실행 확인

### 마을 외교와 적 거점 (스키마 3)

현재 게임은 `schemaVersion: 4`를 발행하며 서버는 1·2·3·4를 모두 수신한다. 아래 원정·거점 필드는 버전 3에서 도입했다.
NPC 상세에 태생 능력치, 방어·이동 속도와 원정 단계가 추가되었다.
마을 카드의 `knowledge`는 마을마다 알고 있는 위치·성향·위험 보고와 원래 관측 시각·출처를 표시한다.
우호·경계는 원정 목적지 선택에 영향을 주지만 개인의 공격 원한과는 별도다.
적 거점 카드와 지도는 주둔/습격 병력, 인구 상한, 순찰 반경, 누적 웨이브를 표시한다.
출발·도착·귀환·중단·마을 소문·증원·반경 확대·집단 습격·철수 사건도 필터링할 수 있다.
기존 스키마 데이터에서 새 필드가 없으면 해당 영역은 수신 대기로 표시한다.

설계·주기·수치·성능 제한은 `doc/NPC_마을외교_적거점_확장_2026-10-15.md`에 기록했다.

5초 이상 새 스냅샷이 없으면 오래된 데이터로 표시한다. 종료·일시정지·쓰기 실패를 구분해서 단정하지 않는다. 연결이 끊기거나 JSON 읽기에 실패해도 마지막 표시 상태는 보존하고 오류를 알린다. 화면 일시정지는 게임 실행에 영향을 주지 않는다. 새 세션을 받으면 선택한 NPC를 해제한다.

빌드·게임 실행·서버 실행·브라우저 결과 확인은 사용자 요청에 따라 수행하지 않았다. 소스 정렬, JS 문법, 프로젝트 XML과 파일 등록만 검사했다.

사용자 확인 순서:

1. 새 빌드 실행 후 실행 파일 옆 `NpcAI/monitor.json`이 갱신되는지 확인.
2. 로컬 서버 실행 후 페이지의 실시간 연결 표시와 NPC 1명을 선택해 상태 변화를 확인.
3. 보스 해금 전후 비활성/활성 집계, NPC 사망, 변이 잔재 생성 시 개체 수 확인.
4. 주민이 마을 밖으로 이동할 때 소속 인구는 유지되고 체류 인원만 변하는지 확인.
5. 게임 종료 후 5초 이상 지나면 데이터 갱신 중단 표시가 나오는지 확인.
6. 서버 재시작 시 자동 재연결, 필터 유지, 새 게임 세션 시 선택 초기화 확인.


## 월드 규모·전서구·이사 (schemaVersion 4)

- 6개 마을의 이름·문화와 초기 직군 비율을 유지하고, 각 생활권을 36×36칸으로 확장했다.
- 마을 중심 간격은 147칸, 이웃 마을 경계 사이 도로는 111칸이다. 일반 걷기 3.7칸/초 기준 30초이며, 중심에서 중심까지는 약 39.7초다.
- `carrierPosts`는 비행 중인 전서구의 출발·도착 마을, 현재 좌표, 발송·도착 시각, 속도, 보고 수를 제공한다. 속도 12칸/초로, NPC 보행보다 빠르다. 발송 당시의 보고를 도착 후 전달한다.
- `villageRoutes`와 `settlementRules`로 지도 도로와 거리·인구 정책을 확인할 수 있다.
- 주민 `migration`, 마을 `immigrants/emigrants/migratingIn/migratingOut`으로 이사를 추적한다. 전입 완료 시 소속·집·장면 그래프의 마을 부모가 함께 바뀐다.
- 전서구 발송·도착·소식과 이사 출발·완료·보류를 사건 필터에서 확인한다. 이사 중에도 도착 전까지 기존 소속 주민으로 집계한다.
- 자발적 이사로 출발 마을의 예정 인구가 50명 미만이 되지 않게 제한한다. 전투 사망까지 막는 인구 보장은 아니다.
- 적 거점은 24×24칸, 초기 12마리·정원 36마리·출격 임계치 24마리·웨이브 16마리다. 거점 수는 5개를 유지한다.
- NPC가 늘어 지도에서는 전체 이름 대신 선택한 주민의 이름을 표시한다. 등록 주민과 이벤트의 개별 조회 기능은 유지한다.
