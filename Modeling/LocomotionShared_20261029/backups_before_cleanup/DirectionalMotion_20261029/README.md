# 화면 위·아래 이동과 방향전환

2026-10-29. 화면 위·아래로 이동하는 동작을 주인공, 공용 NPC, 기존 몬스터 5종, 신규 몬스터 6종에 추가했다. **13개 리그에 각 16개, 총 208개 새 키프레임 동작**이다. 기존 메시와 본·스킨·장비는 그대로 사용하며 방향별 모델 메시를 늘리지 않았다.

기존 `Hero_v1`, `LowPolyKit_v3`, `Monsters_v1`의 원본과 18개 캐릭터 GLB를 갱신했다. 이 폴더는 새 동작 전체의 카탈로그·미리보기·검수·이전 상태 백업을 모은 인계 폴더다. 게임 코드·키 입력 연결·렌더러·빌드는 변경하지 않았다.

## 추가한 동작

아래 접미사 앞에 `HERO_`, `NPC_`, `MON_00_`~`MON_04_`, 또는 `AshWolf_` 등의 기존 모델 접두사가 붙는다.

| 접미사 | 개수 / 리그 | 내용 |
|---|---:|---|
| WalkScreenUp / WalkScreenDown | 2 | 화면 위쪽의 뒷모습·아래쪽의 앞모습으로 걷기 |
| RunScreenUp / RunScreenDown | 2 | 같은 방향으로 달리기 |
| IdleScreenUp / IdleScreenDown | 2 | 해당 방향을 유지한 대기; 이동과 회전의 연결용 |
| TurnStep_L45 / R45 / L90 / R90 / L180 / R180 | 6 | 현재 정면에서 발을 옮기며 좌·우로 방향 바꾸기 |
| TurnScreenUpToDown_L / R | 2 | 위쪽을 보다가 왼쪽 또는 오른쪽 경로로 돌아 아래쪽 보기 |
| TurnScreenDownToUp_L / R | 2 | 아래쪽을 보다가 왼쪽 또는 오른쪽 경로로 돌아 위쪽 보기 |

걷기·달리기는 기존 캐릭터의 보행 위상과 장비 자세를 공유한다. 3D 모델이므로 앞·뒤 방향을 위해 반대 보행을 새로 만들거나 이미지를 좌우 반전하지 않는다. 같은 골격 보행을 실제 방향으로 돌려 본의 키프레임으로 저장했다. 주인공의 왼손 램프와 오른손 검도 바뀌지 않는다.

방향전환은 새로 제작한 발 디딤 동작이다. 사람은 2개의 발을, 동물은 4개의 발을 차례로 옮긴다. 접지한 발의 목표 위치를 유지하고 들어 올린 발을 회전 방향의 호로 이동시킨 뒤, 관절 결과를 본의 위치·쿼터니언·스케일 키로 구웠다. 머리·몸통의 선행 회전, 꼬리·망토·램프의 작은 후행 움직임을 포함한다. 재생 시 IK·천 물리·드라이버는 필요 없다.

소스는 60fps, 주요 방향전환 키는 2프레임 간격이며 GLB는 60fps로 샘플링했다. 새 GLB 클립의 시간은 0에서 시작한다. 기존 클립의 이름·시간·키 채널은 유지한다. 이동은 제자리이며 실제 월드 이동은 적용 작업에서 수행한다.

## 현재 화면과 방향의 대응

현재 게임은 사선 투영이다. 화면의 위쪽은 지면 벡터 `(-1,-1)`, 아래쪽은 `(1,1)`이다. 이를 기준으로 `ScreenUp`은 Blender Z축 -135도, `ScreenDown`은 +45도를 root에 구웠다. Blender 정면 -Y, GLB 정면 +Z, 미터 단위를 유지한다.

**Screen으로 시작하는 방향 동작은 Actor/기본 yaw를 0으로 두고 사용한다.** 현재 `RendererModels.cpp`의 character 기본 좌·우 회전 `-.44 / 2.01`을 이 클립에 다시 곱하면 화면 위·아래와 어긋난다. 다른 적용 작업에서 이 새 클립을 선택할 때 해당 기본 회전을 생략해야 한다. 향후 카메라의 평면 방향이 달라지면 이 화면 방향 규약도 다시 매핑해야 한다.

두 종류의 회전 연결 방식은 다음과 같다.

- `TurnScreenUpToDown_*`를 마치면 Actor yaw 0을 유지하고 `IdleScreenDown`, `WalkScreenDown`, `RunScreenDown`으로 연결한다. 반대 전환도 동일하다. 이미 절대 방향을 포함했으므로 Actor에 180도를 추가하지 않는다.
- `TurnStep_*`는 기존 정면 기준 상대 회전이다. 끝에서 yaw 델타를 Actor에 한 번 넘긴 뒤, root yaw 0인 기존 Idle/Walk/Run으로 연결한다. 재생 중 모델 회전과 Actor 회전을 중복 적용하지 않는다.

방향별 이동 사이에는 보행 위상을 유지한다. 접지 발 전환을 해치지 않도록 기본 0.12초 블렌드 값을 제공하며, 정확한 보간과 입력 처리는 다른 작업에서 구현한다. 기존 45·90·180도 Turn 클립은 호환을 위해 남기고 새 디딤 동작은 `TurnStep` 이름으로 구분했다. 회전 클립은 단발, 걷기·달리기·방향별 대기는 반복이다.

## 갱신 파일

| 원본 / 파일 | 현재 클립 수 |
|---|---:|
| Hero_v1/hero_v1.blend 및 hero_rigged.glb | HERO 33개 |
| LowPolyKit_v3/lowpoly_kit_v3.blend 및 npc_parts_rigged.glb | NPC 61개 |
| LowPolyKit_v3/npc의 직군별 5개 GLB | 각각 같은 NPC 61개 |
| LowPolyKit_v3/monsters의 기존 5종 GLB | 합계 159개 |
| Monsters_v1/monsters_v1.blend 및 신규 6종 GLB | 합계 219개 |

모델·메시 이름, NPC 파트 인덱스, 리그 이름, 기존 클립 이름은 유지했다. 몬스터 종류 3·4와 기존 `MON_03`·`MON_04`의 서로 다른 의미도 변경하지 않았다. 공격·타격·회복·방벽·분노 등 기존 동작과 이벤트 시간을 유지했다.

- `motion_catalog.json`: 208개 새 클립의 이름·루프·길이·방향·회전 연결 규칙·대응 파일
- `validation.json`: 13개 리그와 18개 GLB의 검수 결과
- `delivery_files.json`: 갱신 모델·원본·카탈로그·검수 파일의 SHA256
- `previews/hero_up_down.gif`: 주인공 위·아래 보행 비교
- `previews/turns_overview.gif`: 주인공·기사·늑대·곰·사슴·아자르 방향전환 비교
- `previews/<접두사>_TurnScreenUpToDown_L.gif`: 13종 각각의 방향전환
- `previews/*_keyframes.jpg`: 동작 진행 단계 비교
- `backups/`: 작업 전 모델·원본·카탈로그·문서; `before_sha256.json`으로 대응

미리보기는 실제 GLB를 Blender에 새로 불러와 렌더했다. GIF는 가독성을 위해 전환 끝에서 잠깐 멈추고 반복하며, 여러 캐릭터 비교 GIF는 길이가 다른 동작을 같은 진행률로 맞춰 보여준다. 실제 게임 클립 길이는 카탈로그 기준이다.

메시·웨이트·바인드와 기존 애니메이션을 이전 GLB와 비교했다. 기존 포즈 행렬 오차는 약 0.000001 이하였고, 새 방향 벡터·루프 연결·길이·유한 키·제자리 이동을 검사했다. 실제 스키닝 검사에서 표본 프레임의 가장 낮은 바닥 오차는 약 -1.71mm로 3mm 기준 안이다. 이 검사는 모든 장비 조합의 실시간 충돌이나 게임 내 입력 연결 검증을 대신하지 않는다.
