# 다크 판타지 로우폴리 모델링 키트 v1

2026-10-20. 게임 기획서의 쇠락한 중세, 불·성역·오염의 대비에 맞춘 첫 모델링 세트다. 게임 소스 변경, 빌드, 게임 내 적용은 하지 않았다.

## 캐릭터 규격

맨발 기준 키 1.8m, 머리 높이 약 0.6m인 3등신이다. 머리카락은 정수리 위로 조금 돌출된다. 플랫 셰이딩과 단색 PBR 재질을 사용하며 외부 텍스처 의존성이 없다. UV 텍스처와 아틀라스는 포함하지 않는다.

남성 머리는 넓은 턱·눈썹·짧은 수염, 여성 머리는 좁은 얼굴·가는 눈썹·작은 귀 장식으로 구분했다. 긴머리와 짧은머리는 양쪽 머리에 공용이다. 옷을 성별마다 복제하지 않도록 몸통과 팔다리 체형은 공유한다.

성직자는 사제복·스톨·지팡이, 기사는 철 갑옷·칼, 모험가는 배낭·멜빵, 약탈자는 붉은 사선 띠·등 장비, 상인은 양옆 주머니로 구분한다. 프리뷰의 열 순서는 성직자 → 기사 → 모험가 → 약탈자 → 상인이다. 각 열의 행 순서는 남/짧음, 남/김, 여/짧음, 여/김이다.

## 파트 조립 규약

메시 이름은 `NPC_<SLOT>_<두 자리 파트 인덱스>_<설명>`이다. 예: `NPC_HEAD_00_Male`, `NPC_TORSO_01_Armor`. 메시 오브젝트와 데이터에도 이름을 부여했다. `slot_index`, `part_index`, `slot`, `joint_pivot` 사용자 속성을 원본과 GLB extras에 기록했다. JSON이 전체 정보의 기준이다.

`part_indices` 배열은 다음 슬롯 순서를 따른다. 인덱스는 슬롯 안에서만 유일하다. 비어 있는 슬롯은 **-1**이다. v1 인덱스는 재정렬하지 말고 신규 항목을 뒤에 추가한다.

| 슬롯 인덱스 | 슬롯 | 파트 인덱스 |
|---:|---|---|
| 0 | head | 0 남성 / 1 여성 |
| 1 | hair | 0 짧은머리 / 1 긴머리 |
| 2 | torso | 0 튜닉 / 1 갑옷 / 2 사제복 |
| 3–4 | upper_arm_l / upper_arm_r | 0 튜닉 / 1 갑옷 / 2 사제복 |
| 5–6 | forearm_l / forearm_r | 0 튜닉 / 1 갑옷 / 2 사제복 |
| 7–8 | hand_l / hand_r | 0 공용 손 |
| 9 | pelvis | 0 바지·벨트 / 1 갑옷·벨트 |
| 10–11 | thigh_l / thigh_r | 0 바지 / 1 갑옷 |
| 12–13 | shin_l / shin_r | 0 바지 / 1 갑옷 |
| 14–15 | foot_l / foot_r | 0 공용 부츠 |
| 16 | skirt | 0 사제복 하단 |
| 17 | accessory_back | 0 여행 배낭·멜빵 / 1 약탈자 장비·사선 띠 |
| 18 | accessory_waist | 0 상인 주머니 / 1 기사 칼 |
| 19 | accessory_hand | 0 성직자 지팡이 |

모든 NPC 파트는 발바닥 중앙을 공통 원점으로 가지며 바인드 자세의 위치가 정점에 들어 있다. **조립 시 선택한 파트의 로컬 이동·회전을 0, 스케일을 1로 둔다.** `joint_pivot`을 메시 이동값으로 적용하면 안 된다. 이는 후속 리깅에 참고할 관절 위치다. 왼쪽·오른쪽은 캐릭터 자신의 기준이다.

사제복 하단을 사용하면 pelvis·thigh_l/r·shin_l/r를 -1로 비우며 발은 유지한다. 한 슬롯에는 하나의 파트만 선택한다. 프리셋의 이 규칙을 따르면 기본 의상 조립에서 중복된 하의가 생기지 않는다. 모든 임의 조합·극단적인 포즈의 간섭까지 검증한 것은 아니다.

직군 인덱스는 현 `NpcRole` 순서와 동일하게 0 Priest, 1 Knight, 2 Adventurer, 3 Raider, 4 Merchant다. `sex_index`와 `hair_style_index`는 각각 head·hair 인덱스와 같다.

## 주민 외형 정보

`npc_appearance_assignments.json`은 현 `NpcWorld.cpp`의 이름·직군 배열, `Villages.h`의 마을 순서, `GameRules.h`의 `VillageInitialPopulation`을 읽은 시점의 별도 에셋 데이터다. 현재 주민은 마을당 **56명, 6개 마을 총 336명**이다. 오래된 문서의 48명과 다르다. 메시를 336세트 복제하지 않고 각 주민에 `npc_id`, `village_id`, `name`, `role_index`, `sex_index`, `hair_style_index`, `preset_id`, `part_indices`를 저장했다.

성별과 헤어는 기존 게임 설정에서 읽은 값이 아니라 이번 모델링에서 제안한 외형 배정이다. 아직 게임에는 연결되어 있지 않다. 인구·생성 순서·직군이 후속 작업에서 바뀌면 ID와 직군 대응을 다시 확인해야 한다.

## 원본과 교환 파일

Blender는 미터·Z 위·정면 -Y, GLB는 미터·Y 위·정면 +Z다. GLB 내 좌표는 exporter가 변환한다. JSON에는 관절 기준점을 양쪽 좌표계로 제공한다. 후속 렌더러의 축·손잡이 규약에 맞춘 변환은 적용 작업에서 처리한다.

원본의 `NPC_PART_LIBRARY`, `PROP_LIBRARY`는 공통 원점에 놓인 에셋이며 겹쳐 보이지 않도록 숨겨 두었다. 필요한 파트만 표시해서 편집한다. `NPC_ASSEMBLY_PREVIEW`, `PROP_PREVIEW`는 같은 메시 데이터를 공유하는 배치 예시다. `PRESENTATION`과 DISPLAY 이름 오브젝트는 전달용 에셋이 아니다.

본·스킨 웨이트·애니메이션·충돌체·LOD는 포함하지 않는다. 팔다리는 후속 리깅에 활용하도록 분리했지만, 정적인 바인드 자세 모델이다. 긴 옷과 긴머리의 애니메이션 간섭은 후속 리깅 단계에서 검토한다.

## 검수

실제 Blender 렌더로 NPC 20조합과 프롭 14개를 확인했다. 라이브러리 이름의 중복, 프리셋 슬롯 길이, 모든 파트 참조의 존재 여부를 검사했다. GLB 및 NPC별 인덱스의 추가 검사 결과는 `validation.json`에 있다. 게임 엔진에서의 렌더링·리깅·성능 검증은 아직 진행하지 않았다.
