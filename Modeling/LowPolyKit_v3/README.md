## 리깅 규격

NPC와 몬스터는 같은 이름의 **31개 본**을 사용한다. 몬스터는 체격에 맞춰 바인드 뼈대와 모델 크기를 조정했다. 모든 변형 정점에 정규화된 웨이트가 들어 있으며, glTF의 skin·JOINTS_0·WEIGHTS_0·역바인드 행렬로 전달한다.

| 본 영역 | 구성 |
|---|---|
| 중심 | root → hips → spine → chest → neck → head, jaw |
| 팔 | clavicle_l/r → upper_arm_l/r → forearm_l/r → hand_l/r |
| 다리 | thigh_l/r → shin_l/r → foot_l/r → toe_l/r |
| 장비 | weapon_l/r: 손 아래의 장비 본 |
| 긴 옷 | skirt_front/back/l/r: 골반 아래의 의복 본 |
| 변이체 | tail → tail_tip |

교체형 팔다리·머리·투구·장비는 해당 본에 고정된 웨이트를 갖는다. 몸통은 spine/chest, 사제복 하단은 hips/의복 본으로 웨이트를 나눴다. 사제복의 앉기·무릎 꿇기에서는 밑단을 끌어올리는 의복 키도 사용한다. 물리 천 시뮬레이션이나 머리카락 물리는 포함하지 않는다.

모든 NPC 파트의 로컬 이동·회전은 0, 스케일은 1로 조립한다. 본 이름·부모·바인드 좌표는 `asset_catalog.json`의 `bone_schema`를 기준으로 한다. Blender는 미터·Z 위·정면 -Y, GLB는 미터·Y 위·정면 +Z다. 본 이름이 같더라도 몬스터와 NPC의 크기가 다르므로 이동 채널은 바인드 체격 비율을 반영해야 한다. 몬스터별 전달 파일에는 이미 해당 체격용 클립을 넣었다.

v2의 21개 슬롯과 기존 파트 인덱스는 유지한다. **폐쇄형 투구의 빈 머리 문제는 v3에서 수정했다.** 머리 장비 0의 옆·뒤 보호판을 보강하고, 실제 남녀 머리 메시를 투구 안에 유지한다. 모든 머리 장비는 머리카락만 숨기며 head 슬롯은 sex_index에 맞는 머리를 선택한다. 기존 v2의 투구 0에서 head=-1을 쓰던 규칙을 적용하면 안 된다.

accessory_hand 슬롯 19에 1 검, 2 활, 3 투척 단검, 4 돌, 5 작업 망치, 6 치료약 병을 추가했다. 기존 0은 사제 지팡이다. 활은 왼손, 나머지는 오른손 장비다. 검을 손에 든 기본 기사 프리셋에서는 기존 허리 검 메시를 중복 표시하지 않는다.

## NPC 애니메이션 45개

모두 본의 위치·쿼터니언 회전 키프레임이다. 재생에 드라이버·IK 제약·코드 기반 흔들림이 필요하지 않다. 소스는 60fps 타임라인에 주요 포즈와 중간 키를 배치했고, GLB는 60fps로 샘플링해 전달했다.

| 동작군 | 클립 |
|---|---|
| 대기·인지 | Idle, Observe, Talk, Guard |
| 이동 | Walk, Run, Flee, MoveStart, MoveStop, StrafeL, StrafeR, WalkBack |
| 방향 전환 | Turn_L45/R45, Turn_L90/R90, Turn_L180/R180 |
| 직군 공격 | AttackPriest, AttackKnight, AttackAdventurer, AttackRaider, AttackMerchant |
| 약탈 근접 행동 | RaidMelee |
| 생활·지원 | Work, Trade, Eat, Bless, HealAlly, Purify, DawnOil, Train |
| 휴식 | SitEnter → Rest → SitExit |
| 기도·명상 | KneelEnter → Pray/Reflect → KneelExit |
| 피격·생사·변이 | Hit, Death, DeadHold, GetUp, Spawn, Transform |

실제 이름에는 `NPC_` 접두사가 붙는다. Work·Rest·Pray 등 반복 동작은 루프이며, 방향 전환·진입/이탈·공격·사망 등은 단발이다. 정확한 길이와 루프 여부는 카탈로그를 사용한다.

직군별 공격은 현 `NpcWeaponFor`의 공격 준비와 회복 시간을 기준으로 만들었다.

| 직군 | 동작 | 준비 / 회복 | 타격·발사 이벤트 |
|---|---|---|---|
| 성직자 | 지팡이·성탄 시전 | 0.70 / 0.65초 | 0.70초 |
| 기사 | 검 휘두르기 | 0.40 / 0.45초 | 0.40초 |
| 모험가 | 활 조준·당기기·발사 | 0.55 / 0.50초 | 0.55초 |
| 약탈자 | 단검 투척 | 0.30 / 0.40초 | 0.30초 |
| 상인 | 돌 던지기 | 0.60 / 0.70초 | 0.60초 |

`Raid`는 소스에서 근접 약탈 판정이므로 투척 공격과 별도의 RaidMelee로 연결했다. 19개 NpcAction의 Prepare·Approach·Perform·Recover와 역할별 공격 대응은 `npc_action_map`에 기록했다. 훈련에 공격 클립을 재사용할 경우 이벤트는 시각 용도로만 취급한다.

애니메이션 이벤트는 게임플레이 판정을 호출하는 코드가 아니다. 기존 시뮬레이션의 공격·회복 상태와 동기화하고, 실제 피해·발사 판정은 후속 구현에서 한 번만 처리해야 한다. 현재 게임에서 사망 즉시 그리기를 끄는 경로는 사망 클립을 재생하도록 별도 연결이 필요하다.

## 이동과 방향 전환

걷기·달리기는 위치가 누적되지 않는 **제자리 이동 클립**이다. 좌우 다리를 반 주기 차이로 키프레임화했고, 무릎 굽힘·발 들기·발의 각도 보정과 반대편 팔 흔들기를 넣었다. 보행의 왼발 기준 접지는 정규화 위상 0, 오른발은 0.5다. Walk는 1초/약 0.56m 보폭, Run은 약 0.667초/약 1m 보폭의 시각 기준이다. 현 게임 월드 단위와 미터 변환은 아직 정의되지 않았으므로 적용 시 속도와 재생률을 맞춘다.

방향 전환은 몸통·머리가 먼저 반응하고 root가 좌우 45·90·180도로 회전하는 실제 키프레임 클립이다. **회전 델타를 가진 단발 클립**이며 끝에서 방향을 0으로 되돌리지 않는다. 애니메이션 root 회전 또는 actor 방향 누적 중 한쪽에서만 회전을 반영한다. 이중 적용하면 방향이 두 배로 회전한다.

권장 전환은 0.12초 크로스페이드다. 걷기↔달리기는 발 위상을 유지하고, 임의 방향 사이의 연속 보간에는 최단 경로 쿼터니언 보간을 사용한다. 전환용 모델 동작과 메타데이터를 전달했으며, 애니메이션 상태 머신·블렌드 트리 자체는 후속 구현 대상이다.

잔재와 변이체는 같은 메시 데이터를 공유해 불필요한 형상 복제를 줄였다. 별도 GLB 파일로 전달할 때는 각각 독립적으로 사용할 수 있도록 동일 형상이 포함된다. 원본 `.blend`에서는 데이터 링크를 유지한다.

기존 프롭 14개를 유지하고 바위, 나무 묘표, 훈련 허수아비, 거점 깃발, 마을 작업장, 무너진 성당, 나뭇잎이 남은 나무, 가시덤불, 풀 3종, 잔해 더미, 포장길·흙·오염 지면, 울타리, 그루터기, 랜턴, 우물을 추가했다. 어두운 석재·목재·낡은 천과 잔불 색을 이어 사용한다.

**게임의 prop kind와 에셋 prop_index는 별도 번호 체계다.** 다음 표 또는 `game_prop_mapping`을 사용한다.

## 원본 확인 방법과 검수

`NPC_PART_LIBRARY`, `MONSTER_LIBRARY`, `PROP_LIBRARY`, `RIG_LIBRARY`는 라이브러리다. 전시 모델과 겹치지 않게 숨긴다. `NPC_ROLE_PREVIEWS`와 `PROP_PREVIEW`는 메시 데이터를 공유하는 전시용이며, DISPLAY/PRESENTATION 오브젝트는 게임 에셋이 아니다. 전시 리그를 선택해 Action Editor에서 클립을 바꾸거나 타임라인을 재생해 확인할 수 있다. 원본 리그에는 클립마다 같은 이름의 NLA 트랙이 있고 기본적으로 mute했다. 재생할 트랙 하나를 활성화하거나 Action을 직접 선택한다.

모든 정점의 웨이트 유무·합계, GLB에 실제 skin과 클립이 존재하는지, 루프의 시작/끝 포즈 일치, 키 값의 유한성, 19개 행동과 10개 프롭 종류 대응, 직군별 이벤트 시점을 검사했다. 실제 모델 렌더와 짧은 GIF로 이동·공격·회전·광역 시전도 확인했다. 기사·수문장 GLB를 새 Blender 장면으로 다시 가져와 각각 31개 본과 45/17개 클립이 복구되고, Run/Burst 재생 시 정점이 실제로 움직이는 것도 검사했다. `previews/helmet_three_views.jpg`에서 수정된 기사 투구의 정면·측면·후면을 확인할 수 있다. 엔진 내 적용·충돌·모든 의상 조합과 극단 포즈의 관통 검사는 아직 하지 않았다.

발사체 메시를 궤적으로 날리거나 손의 돌·단검을 숨기는 처리는 메타데이터의 이벤트 시점에 런타임이 수행해야 한다. 생활 행동에서는 `equipment_hand_index`를 참고해 무기를 작업 도구·치료약 또는 빈손으로 바꾼다. GLB의 기본 노드 가시성만으로 자동 장비 교체가 실행되지는 않는다.
